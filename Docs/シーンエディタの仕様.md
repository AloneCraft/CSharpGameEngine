# シーンエディタの仕様

## 1. 設計原則

シーンエディタは Unity の操作体系を基本としつつ、Unreal Engine、Blender、Maya などの優れた操作を選択的に採用する。

基本原則:

- 永続的なモードや隠れた状態を最小化する。
- メニュー選択より直接操作を優先する。
- モード切替より「キーを押している間だけ有効」な一時操作を優先する。
- 修飾キーの意味は可能な限り一貫させる。
- 物理キーと操作概念を分離し、入力プリセットを変更可能にする。
- Scene View はゲーム実行時の Camera と独立させる。
- Transform 操作と、Camera / Light などの固有プロパティ操作は組み合わせ可能にする。
- シーン編集と宣言コード編集は双方向で同期する。
- Visual Editor と Code Editor のどちらから編集しても、同じ論理シーンを編集している状態にする。

---

## 2. 主要概念

| 概念 | 推奨識別子 | 意味 |
|---|---|---|
| シーンビュー | `SceneView` | ゲームカメラとは独立した編集用3Dビュー |
| シーンビュー状態 | `SceneViewState` | 視点位置、回転、注視点、投影方式など |
| 注視点 | `Focus` | Orbit / Zoom / Navigation の基準 |
| 注視位置 | `FocusPosition` | Focus の論理座標 |
| 注視距離 | `FocusDistance` | SceneView と Focus の論理距離 |
| ナビゲーション | `Navigation` | SceneView の操作全般 |
| ナビゲーションスケール | `NavigationScale` | 現在の編集スケールに応じた移動量基準 |
| Transform操作 | `TransformOperation` | Move / Rotate / Scale |
| 操作修飾 | `InteractionModifier` | 一時的に操作へ付加する意味 |
| 視点追従 | `FollowView` | 対象操作に SceneView を追従させる |
| 複製 | `Duplicate` | 操作開始時に複製して複製物を操作する |
| スナップ | `Snap` | 操作値を拘束する |
| 頂点スナップ | `VertexSnap` | Position を頂点に合わせる |
| 面スナップ | `SurfaceSnap` | Position を面に合わせ、Rotation を法線に合わせる |
| 座標空間 | `TransformSpace` | World / Local |
| 投影方式 | `ProjectionMode` | Perspective / Orthographic |
| ギズモ | `Gizmo` | シーン内の編集用操作UI |
| プロパティギズモ | `PropertyGizmo` | コンポーネント固有の空間プロパティ編集UI |
| 複合ギズモ | `CompoundGizmo` | Transform Gizmo と Property Gizmo の合成 |
| 宣言シーン | `SceneDeclaration` | シーン内容を表現する宣言コード |
| シーン同期 | `SceneSync` | シーンとコードの双方向同期 |

## 3. 永続状態

永続状態は最小限にする。

| 状態 | 値 |
|---|---|
| `ActiveTool` | Select / Move / Rotate / Scale |
| `TransformSpace` | World / Local |
| `ProjectionMode` | Perspective / Orthographic |
| `NavigationPreset` | Default / Unity / Unreal / Blender / Maya / Custom |
| `NavigationSpeedMultiplier` | ナビゲーション速度倍率 |

以下は永続モードにしない。

- `FollowView`
- `Duplicate`
- `VertexSnap`
- `SurfaceSnap`
- `FastNavigation`
- `PrecisionNavigation`

すべてキーを押している間だけ有効にする。

## 4. Scene View ナビゲーション

| 入力 | 操作 | 動作 |
|---|---|---|
| RMB + Mouse | `Look` | マウス移動方向を見る |
| RMB + W/S | `Fly` | 前進 / 後退 |
| RMB + A/D | `Fly` | 左 / 右 |
| RMB + Q/E | `Fly` | 下 / 上 |
| Shift + Navigation | `FastNavigation` | 一時的に高速移動 |
| Ctrl + Navigation | `PrecisionNavigation` | 一時的に低速・高精度移動 |
| RMB + Wheel | `AdjustNavigationSpeed` | Navigation速度倍率変更 |
| MMB Drag | `Pan` | 視線を変えず画面平面上を移動 |
| Alt + LMB Drag | `Orbit` | Focus を中心に旋回 |
| Wheel | `Dolly` | Perspective では前後移動 |
| Wheel | `Zoom` | Orthographic では表示倍率変更 |
| F | `FocusSelection` | 選択対象へ Focus |

### 4.1 Look の向き

デフォルト:

- マウス右 → 右を見る
- マウス左 → 左を見る
- マウス上 → 上を見る
- マウス下 → 下を見る

設定:

- `InvertLookX`
- `InvertLookY`

X / Y は独立して反転可能とする。

## 5. Transform ツール

| 入力 | 操作 |
|---|---|
| W | Move |
| E | Rotate |
| R | Scale |
| LMB | Select |
| Ctrl + LMB | 複数選択追加 / 解除 |
| 空間からLMB Drag | 矩形選択(現在の選択を置換) |
| 空間からCtrl + LMB Drag | 矩形選択(現在の選択へ加算) |

RMB による Navigation 中は、W/E/Q/A/S/D を Navigation が優先して使用する。

Scene Designer上部の`TransformSpace`セレクターで`World`/`Local`を切り替える。選択値は
`SceneEditorSettings`へ保存し、再度ツールウィンドウを開いたときも維持する。複数選択時の
Transformギズモはprimaryの位置を共有Pivot、primaryの回転をLocal基底とし、選択済み祖先を持たない
各selection rootへ同じワールド差分を適用する。

### 5.1 矩形選択

- LMB Down時にオブジェクトへヒットしなかった場合だけ、物理ピクセルで開始点から4px以上移動すると
  `MarqueeSelect`を開始する。4px未満でLMB Upした場合は従来どおり空間クリックとして選択解除する。
- オブジェクト上から始めたドラッグは、移動距離にかかわらず途中で矩形選択へ切り替えない。
  `PendingSelect`を維持し、LMB UpでDown時にヒットした1件を確定する。
- ドラッグ中は開始点と現在点を対角とする矩形を表示する。確定時は各オブジェクトの投影済み
  メッシュ境界矩形との交差(境界接触を含む)で対象を決める。
- 修飾なしは矩形内の全対象で選択を置換する。0件なら選択解除。Ctrl併用は既存選択へ加算し、
  既に選択済みの対象を解除しない。0件なら現状維持する。
- 矩形内対象は描画順で発行し、最後の対象をprimaryとする。Viewportは全対象を複数選択として
  ハイライトする。現行WPF TreeViewは単一選択のため、Hierarchyにはprimaryだけを表示する。
- `MarqueeSelect`開始後はLMB Upまたはpointer capture喪失まで操作を固定し、途中のRMB/MMBで
  Navigationへ切り替えない。capture喪失またはEscでは確定せず矩形を消す。

## 6. Transform 修飾操作

### 6.1 Shift + Gizmo = Follow View

`Shift + Gizmo Drag`

意味:

> 対象の編集に対して SceneView が追従し、対象との視覚的な関係を維持する。

#### Move

- Object Position を変更
- SceneView Position に同じ移動差分を加える
- FocusPosition に同じ移動差分を加える

概念:

```text
Object.Position    += ΔP
SceneView.Position += ΔP
FocusPosition      += ΔP
```

#### Rotate

- Object を回転
- 同じ Pivot を中心に SceneView も同じ回転差分だけ旋回
- SceneView Rotation にも同じ回転差分を適用

概念:

```text
SceneView.Position =
    Pivot + ΔR * (SceneView.Position - Pivot)

SceneView.Rotation =
    ΔR * SceneView.Rotation
```

#### Scale

デフォルトでは SceneView を Scale に追従させない。

実装上はドラッグ開始時の視点を捕捉し、Shiftを押しているMoveイベントでは開始時からの総差分を
再適用する。Shiftを離した間は直前の視点を維持し、再押下時は現在の総差分へ追いつく。
Escまたはpointer capture喪失では視点も開始時へ戻し、MouseUp確定時は追従後の視点を維持する。

---

### 6.2 Alt + Gizmo = Duplicate

`Alt + Gizmo Drag`

- 操作開始時に選択対象を複製する
- 複製物を新しい Selection にする
- 複製物へそのまま Move / Rotate / Scale を継続する
- 元オブジェクトは変更しない
- Alt+LMBでギズモハンドルにヒットした場合はDuplicateをOrbitより優先し、ハンドルに
  ヒットしない場合だけ従来どおりOrbitを開始する
- Scene Rootは兄弟へ追加できないため複製対象外とする
- 複数選択は選択済み祖先を持たないrootを選択順で各親のChildren末尾へ追加する
- MouseUpでは「構文triviaを含む複製、Name一意化、最終Transform」を1 Undoで確定し、
  再解析で予測した全NodePathが解決した時点で複製rootを新しいSelectionにする

概念としては独立ツールではなく、

```text
TransformOperation + Duplicate
```

と扱う。

---

### 6.3 Ctrl + Gizmo = Snap

`Ctrl + Gizmo Drag`

現在の TransformOperation に応じて Grid / Increment Snap を行う。

- Move: 選択中の軸/平面成分を1.0単位へ丸める。
- Rotate: リングの回転角を15°単位へ丸める。
- Scale: 選択中の軸または均一倍率を0.1単位へ丸め、最小倍率を0.1とする。
- Ctrlの押下状態はドラッグ中の各Moveイベントで評価し、押下中だけスナップする。

識別子:

`Snap`

---

## 7. Vertex / Surface Snap

### 7.1 Vertex Snap

入力:

```text
V + Drag
```

識別子:

`VertexSnap`

動作:

- Position を対象頂点へ合わせる
- Rotation は変更しない
- V を押している間だけ有効
- Moveドラッグ中だけ有効
- ドラッグ対象のselection rootと全子孫は候補から除外する
- 物理ピクセル半径8px以内で最も近い投影頂点を選ぶ
- `Shift+V` によるトグルモードは採用しない

概念:

```text
Target      = Vertex
Affects     = Position
Rotation    = Unchanged
Persistence = HoldOnly
```

---

### 7.2 Surface Snap

入力:

```text
N + Drag
```

識別子:

`SurfaceSnap`

動作:

- Position を対象面へ合わせる
- Rotation を面法線へ合わせる
- N を押している間だけ有効
- Moveドラッグ中だけ有効
- ドラッグ対象のselection rootと全子孫は候補から除外する
- primaryのローカル+Yを最近ヒット三角形の幾何法線へ整列する
- N/V/Ctrlを同時に押した場合の成功クエリ優先順位はSurface → Vertex → Increment Snap
- 全selection rootのPosition+Rotationがliteral/defaultとして編集可能な場合だけSurfaceを適用し、
  式を保持するRotationは暗黙に上書きしない

概念:

```text
Target      = Surface
Affects     = Position + Rotation
Rotation    = AlignToSurfaceNormal
Persistence = HoldOnly
```

設定:

```text
SurfaceSnap.AlignRotationToNormal = true
```

Phase 5の製品経路は既定値trueを固定で使用する。Rotation整列だけを無効化する設定UIは
将来拡張とし、永続設定項目はPhase 5では追加しない。

## 8. Gizmo アーキテクチャ

ギズモは置き換えではなく合成する。

```text
CompoundGizmo
├─ TransformGizmo
│  ├─ MoveHandle
│  ├─ RotateHandle
│  └─ ScaleHandle
└─ PropertyGizmo
   ├─ DistanceHandle
   ├─ RadiusHandle
   ├─ AngleHandle
   ├─ DirectionHandle
   ├─ ExtentHandle
   └─ PlaneHandle
```

原則:

> Transform は TransformGizmo で編集し、コンポーネント固有の空間プロパティは PropertyGizmo で編集する。

コンポーネント専用ギズモへ完全に切り替えず、汎用 TransformGizmo と固有 PropertyGizmo を同時表示する。

```text

= TransformGizmo
+ FrustumGizmo
```

| Rotate Gizmo | Camera Rotation |
| Frustum Angle | Field Of View |
| Near Plane | Near Clip |
| Far Plane | Far Clip |

Camera でも通常オブジェクトと同じ Move / Rotate 操作を維持する。


### 10.2 Spot Light

```text

= TransformGizmo
+ DirectionGizmo
+ InnerConeGizmo
```

編集可能:

```text

= TransformGizmo
```

## 11. Property Gizmo と修飾キー

修飾キーは適用可能な操作にのみ作用する。

| Modifier | Transform Gizmo | Property Gizmo |
|---|---:|---:|
| Shift / FollowView | ○ | 必要な場合のみ |
| Ctrl / Snap | ○ | ○ |
| Alt / Duplicate | ○ | 原則 × |

Phase 6のPropertyGizmoでは、Shiftは全handleで不適用、Ctrlは角度・方向・距離の単位snap、
Altは全handleで不適用とする。Alt押下時はProperty hitを除外し、Transform handleならDuplicate、
それ以外ならOrbitという既存優先順位へ戻す。

例:

```text
Ctrl + Spot Cone Drag
→ 角度を一定単位で Snap

Ctrl + Light Range Drag
→ Range を一定単位で Snap
```

## 12. 入力優先順位

推奨優先順位:

1. Modal Editor Operation
2. Active Scene Navigation
3. Active Gizmo Manipulation
4. Object Selection
5. Context Menu

例:

- RMB Drag 中は Selection と Gizmo 操作を開始しない
- Gizmo Drag 中は Pointer をその操作が占有する
- Esc で現在の一時操作を可能な限りキャンセルする

## 13. Declarative Scene

シーンはコードとして宣言可能にする。

識別子:

`SceneDeclaration`

概念例:

```csharp
Scene("Main", scene =>
{
    scene.Object("Camera")
        .Position(0, 2, -10)
        .Rotation(0, 0, 0)
        .Camera(fov: 60);

    scene.Object("KeyLight")
        .Position(3, 5, -2)
        .Rotation(45, -30, 0)
        .SpotLight(
            range: 20,
            innerAngle: 20,
            outerAngle: 40);
});
```

正確な宣言構文は別仕様とする。

重要なのは、各 Entity / Component / Property が安定した識別子を持つこと。

## 14. Scene Editor と宣言コードの双方向同期

Scene Editor と SceneDeclaration は同じ論理シーンを表す。

```text
Scene Editor
     ⇅
SceneSync
     ⇅
SceneDeclaration
```

どちらか一方を単なるエクスポート先にはしない。

### 14.1 Scene Editor → Code

Scene Editor で変更した内容を宣言コードへ反映する。

対象例:

- Entity 追加
- Entity 削除
- Entity 名変更
- Parent 変更
- Position / Rotation / Scale
- Component 追加 / 削除
- Component Property 変更
- Camera Property
- Light Property
- Gizmo から編集された Property
- Duplicate による Entity 生成

例:

```text
Scene Editor:
Light.Range 10 → 20

↓ SceneSync

SceneDeclaration:
.Range(20)
```

---

### 14.2 Code → Scene Editor

SceneDeclaration を変更した場合、Scene Editor に即時反映する。

対象例:

- Position のコード値を書き換える
- Entity を追加する
- Entity を削除する
- Component を追加 / 削除する
- Camera FOV を変更する
- Light Range を変更する
- Parent を変更する

例:

```text
Code:
.Position(10, 5, 0)

↓ SceneSync

Scene Editor:
Object が新しい Position に移動
```

## 15. 双方向同期の原則

### 15.1 単一の論理モデル

Visual Scene と Code Scene を別々の真実として管理しない。

推奨構造:

```text
SceneDeclaration / Syntax
          ⇅
      SceneModel
          ⇅
      Scene Editor
```

論理的には `SceneModel` が編集対象を表す。

Scene Editor は SceneModel を視覚操作し、Code Editor は同じ SceneModel を宣言コードとして編集する。

---

### 15.2 Stable Identity

Entity には表示名とは別に安定した識別子を持たせる。

例:

```text
EntityId
ComponentId
PropertyPath
```

表示名変更で参照が壊れないようにする。

---

### 15.3 Property 単位同期

可能な限りファイル全体を作り直さず、変更された意味単位で同期する。

例:

```text
Entity.Transform.Position.X
Light.Range
Camera.FieldOfView
```

これにより:

- Code の不要な整形変更を防ぐ
- コメントを保持する
- 手書きコードを極力維持する
- Undo / Redo を小さな単位で扱える

---

### 15.4 Scene Editor 編集時のコード保持

Scene Editor が宣言コードを書き換える場合:

- 関係ないコードを再生成しない
- コメントを保持する
- ユーザーの改行や周辺構造を可能な限り保持する
- 対応する Syntax Node のみ変更する
- 全ファイル生成は最終手段とする

---

### 15.5 Code 編集時の反映

コード変更後:

1. Syntax を解析
2. SceneDeclaration の差分を取得
3. SceneModel に差分適用
4. Scene Editor 表示を更新

全面的なシーン再生成ではなく、可能な限り差分適用する。

---

## 16. 編集トランザクション

Scene Editor の一回のユーザー操作を一つの編集トランザクションとして扱う。

例:

```text
Gizmo MouseDown
    ↓
BeginTransaction

Drag
    ↓
Preview Changes

MouseUp
    ↓
CommitTransaction
    ↓
SceneModel 更新
    ↓
SceneDeclaration 更新
```

これにより Undo / Redo とコード更新単位を一致させる。

---

## 17. Undo / Redo

Undo / Redo は Visual Editor と Code Editor で可能な限り共通化する。

例:

```text
Gizmo Move
→ Code Position 変更
→ Ctrl+Z
→ Scene と Code の両方が元に戻る
```

SceneModel の編集履歴を中心に扱う。

---

## 18. 外部コード変更

SceneDeclaration ファイルが外部エディタや AI によって変更された場合も監視する。

```text
File Changed
    ↓
Parse
    ↓
Semantic Diff
    ↓
SceneModel Patch
    ↓
Scene View Refresh
```

変更が Scene Editor の未確定編集と競合した場合は、自動上書きせず競合として扱う。

---

## 19. 同期競合

同一 Property が同時に変更された場合:

```text
Scene Editor:
Position.X = 10

Code:
Position.X = 20
```

未確定 Scene Editor 操作中は Code 側変更を即時上書きしない。

推奨:

- 操作中の値をロック
- 操作終了時に競合検出
- 自動解決可能なら差分統合
- 解決不能ならユーザーへ競合表示

通常操作で競合が頻発しない設計を優先する。

---

## 20. Scene View 自体は SceneDeclaration に保存しない

SceneView は編集支援状態でありゲームシーンの一部ではない。

原則として以下は SceneDeclaration へ書き込まない。

- SceneView Position
- SceneView Rotation
- FocusPosition
- NavigationSpeed
- Gizmo visibility
- Editor selection

必要なら Editor Session / Workspace State として別保存する。

## 23. 最上位設計ルール

> 永続モードは最小限にし、通常操作を修飾キーで一時的かつ直交的に拡張する。

> Transform とコンポーネント固有プロパティは別概念として扱いながら、Scene 上では Compound Gizmo として合成する。

> Scene Editor と宣言コードは別々の成果物ではなく、同じ SceneModel を編集する二つのインターフェースとして扱う。

> Scene Editor で編集すれば宣言コードへ反映し、宣言コードを編集すれば Scene Editor へ反映する。

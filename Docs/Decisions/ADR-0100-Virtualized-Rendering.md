# ADR-0100 — 仮想化描画: GPU シーン、仮想ジオメトリ、仮想シャドウ、VirtualObject、地形、仮想テクスチャ
- 状態: Accepted(2026-11-16。ユーザーの依頼:「Omni に VirtualGeometry(Meshlet)、VirtualShadowMaps(VSM)、VirtualObject が実装されている。これを参考に実装して。これに VirtualTexturing(RVT)を統合して。CSharpGameEngine はレガシーがないのでよりきれいに実装できるならして」。計画はユーザーが承認した)
- 位置づけ: ADR-0098 の段階 D(1.0 公開後に広げる作業)の前倒し。`Docs/目標、ロードマップ、戦略.md` は変えない(ユーザーの判断)。同文書 2.3 の「UE と同じ見た目は目指さない」も変えない。目的は UE の複製ではなく、細かいメッシュと広い地形を必要な分だけ読み込んで描くこと
- 関連: ADR-0079(描画のパスはプラグインに置けない)、ADR-0082・ADR-0083(仮想方向光シャドウと柔らかい影。M0132 で置き換える)、ADR-0084(対数の深度)、ADR-0085(描画パス。決定 §2 の表面と照明の分割を先取りする)、ADR-0087(描画の層)、ADR-0098(目標と段階)、ADR-0099(プロジェクトの構成と名前)
- 手本: Unity プロジェクト `G:\Unity\6.6\Omni`(`Assets\Omni\Core\VirtualGeometry`、`Assets\Omni\Core\Runtime\Render\VirtualShadows`、`Docs\Plans\VirtualGeometryArchitecture.md`、`Docs\Plans\VirtualShadowMaps.md`、`Docs\VirtualObjectBrief.md`)。RVT は Omni に無い

## 用語
| 語 | 意味 |
|---|---|
| 仮想ジオメトリ(VG) | メッシュを小さな塊(クラスタ、最大 128 三角形)に分け、粗い版から細かい版までの階層を作っておき、画面で必要な細かさの塊だけを描く仕組み。UE の Nanite に当たる |
| 仮想シャドウ(VSM) | 巨大な影の画像をページ(128×128 画素)に分け、画面に映る所のページだけ作って使い回す仕組み |
| VirtualObject(VO) | 画面上の大きさ(画素)だけで、物の描き方の「段」を切り替える仕組み |
| 仮想テクスチャ(VT)・RVT | テクスチャをページに分け、必要なページだけ持つ仕組み。RVT は、地形の層(土・草・岩・道など)を重ねた結果を実行時にページへ焼いて使い回すもの |
| ページ | 必要な分だけ読み込む・作る単位。足りなければ粗い版で代わりに描く |
| GPU シーン | 全物体の位置と材質を GPU 上の表にまとめたもの。GPU が「どれを描くか」を自分で選べるようになる |
| 間接描画(ExecuteIndirect) | 描く数を CPU ではなく GPU の計算結果で決める描画命令 |
| 番号引き(bindless) | 材質のテクスチャを 1 本の配列に並べ、番号で引く方式。物体ごとの切り替えが要らなくなる |
| Hi-Z | 手前の物に隠れた塊を描かずに済ませるための、粗い奥行きの画像 |
| WARP | GPU なしで動く検証用のソフトウェア描画。自動検証の必須経路 |
| ゴールデン | 「この場面はこの絵になる」と固定した 7 枚の基準画像 |
| ABI(`stage-v16` など) | シェーダーとエンジンの間の取り決めの版。変えると成果物を作り直す |
| L0 / L4 / L5 / L6 / L7 | 層の番号。L0 は D3D12 を直接操作する層、L4 は描画の計画、L5 はゲームの実行時の部品、L6 は成果物の形式、L7 は前処理 |

## 背景
- 本エンジンの描画は、CPU が 1 物体ずつ描画命令を出す(`StageRenderer.DrawObjects`)。材質は物体ごとの定数とテクスチャの表から読む。GPU 側で選んで描く下地が無い。
- 仮想シャドウは太陽光限定の簡易版がある(M0115)。どのページが要るかは CPU が決め、ページごとに全物体を CPU で判定して描く。計画の関数を L0 が呼んでいる(`StageRenderer.VirtualShadows.cs` の `VirtualShadowCache.Plan`)。
- テクスチャは無圧縮で、全部を常駐させる。地形の仕組みは無い。
- Omni は VG・VSM・VO を実装済みだが、自己分析(`VirtualGeometryArchitecture.md`)が次の弱点を挙げている。
  - ページの管理と GPU からの読み戻しが 4 か所に別々にある(VG のページ、地形の頂点、VSM のページ、色タイル)。
  - VG が VSM へ影を落とせない(接続が未実装)。
  - 古い経路と新しい経路が並んでいる。「Page」という語が 4 つの意味で使われている。画面上の誤差の式が 3 種類ある。
  - メッシュと地形で、材質の解決・影・予算・描けない理由の扱いが違う。

## 決定

### 1. 下回りを共通にする
- 共通にする部品は 4 つ: フレームごとのアップロードの輪、GPU からの読み戻しの輪、空き枠の割り当て(古い順に追い出す)、「描けない理由と予算」の報告。
  - アップロードの輪(M0129 単位 5): 送る命令は次のフレームの最初に記録し、送った一時の置き場や、広げる前の表と記述子の置き場は、それを使ったかもしれないフレームのフェンスが済んでから放す。フェンスの値は、そのフレームを GPU に送るときに付ける。記録の途中で GPU の完了を待つ経路がフェンスの値を進めるので、記録の時点で付けると、まだ送っていないフレームが使う資源を早く放してしまう(実際に、基準画像の試験がネイティブの例外で落ちた)。
  - 読み戻しの輪(M0129 単位 5): フレームの枠ごとに置き場を 1 つ持ち、枠がまた回ってきたとき(描画器はその枠のフェンスを待ってから使い直す)に、GPU を待たずに読む。影と主パスの時間の計測をこれに載せた。
- ページ表とキーは技術ごとに持つ。VG は親子の依存、VSM は輪になった格子と無効化、VT は親への代替と、中身が違うため。使い手との界面は、2 つ目の使い手(VSM)ができた時点で固める。
- 画面上の大きさの式は 1 つにする。VG の塊、地形のマス、VO の段、テクスチャの細かさで同じ式を使う。CPU とシェーダーで結果が一致することを試験で固定する。
  - L4 の `Streaming/ScreenSizeMetric`(M0129 単位 6)。透視なら「1 メートル先の 1 メートルが何画素か」、正射影なら「1 メートルが何画素か」の係数と、近すぎる距離の下限を持つ。球は表面のいちばん近い所までの距離で測る(小さく見積もらない)。シェーダー側の式は同じ型の文字列(`ScreenSizeMetric.Hlsl`)に置き、計算シェーダーは取り込みを使えないので、使うシェーダーは式を写して持ち、写しが文字まで同じことを試験で固定する(M0130 で決めた)。CPU と GPU の差は相対で 1e-6 以内を約束にする(平方根と割り算の最後の桁)。
  - 空き枠の割り当て `Streaming/PageSlotAllocator` と報告 `StreamingReport`(M0129 単位 6)。キーは使い手が決める 64 ビットの値。要求は渡した順(優先順)に処理し、予算と置き場の数を超えず、固定したページとそのフレームで要求したページは追い出さず、最後に使ったのが最も古いページ(同じならキーの小さいほう)を追い出す。断った理由(予算、満杯)を数える。追い出す候補は今は置き場を全部見て探す(数千の置き場なら十分。足りなくなったら順番の表を持つ)。

### 2. 従来のメッシュも同じ GPU シーンに載せる
- 物体ごとの定数(ObjectCB)をやめ、物体の表と材質の表(構造化バッファ)にする。VG だけ別の材質経路を作らない。
  - 物体の表の 1 件は、位置(World)、保守的なラスタ深度、発光の倍率、選択の重み、材質の番号。材質の表の 1 件は、基本色、粗さと metallic の係数、発光、世界格子。物体と材質を掛け合わせた値(発光 × 倍率、物体に固定する格子の原点)は CPU で合成せず、シェーダーが 2 つの表から求める。
  - 表は 1 フレームに 1 回、今の値で全部書く(フレーム計画の `SceneUpload`)。値を設定した時点では書かない。こうすると、設定を毎フレーム呼び直さなくても、フレームの枠ごとに古い値が残らない。
  - 描画が渡すのは、物体の番号・表示モード・描画の印の 3 つだけ(ルート定数)。頂点シェーダーが物体の番号を画素シェーダーへ渡し、画素シェーダーはそれを使う。後の段階で、頂点シェーダーが番号を別の方法(見える物の一覧)で得るようになっても、画素シェーダーは変わらない。
  - Lumen のカード撮影は、物体の写しを別に作らず、同じ物体を「メッシュ自身の空間で描く」印を付けて描く。
  - 材質のテクスチャは、描画器が持つテクスチャの見え方(テクスチャと sRGB かどうかの組)ごとに 1 つの番号を持ち、材質の表が 4 つの番号を持つ。影の画像はレジスター t4 のまま、環境の表に置く。材質の数に上限は置かず、足りなくなったら材質の表と記述子の置き場を倍に広げる(材質を足すときは GPU の完了を待つので、そのときに作り直せる)。
  - 物体と材質の表は `stage-v17`、番号引きは `stage-v18`。どちらも M0129 の中の版で、古い成果物は拒否して作り直す。仮想ジオメトリの頂点シェーダー(t22〜t25)は `stage-v19`、その影の版は `stage-v20`、物体の向きの法線マップ(b1 の 4 つ目)は `stage-v21`(M0130)。
- 画素シェーダー `PSMain` を「表面の評価」と「照明」に分ける。形は ADR-0085 決定 §2(`EvaluateSurface` が `SurfaceData` を作る)に合わせる。これは ADR-0085 §2 の先取りで、描画パスの追加(Forward/Deferred)は含まない。
- 材質のテクスチャは番号引きにする。間接描画の命令はテクスチャの表を切り替えられないため。
- D3D12 のリソース束縛の段(`GraphicsDevice.ResourceBindingTier`)が 2 以上であることを必須にする。DirectX 12 対応の GPU の大半と WARP は満たす。

### 3. 選択は計算シェーダー、描画は間接描画
- mesh shader、Visibility Buffer、ソフトウェアラスタは使わない。WARP が必須の検証経路であることと、Omni の計測結果(不採用)による。
- 1 つの塊を 1 回分(1 インスタンス)として描く。頂点バッファを使わず、頂点シェーダーが頂点番号とインスタンス番号から構造化バッファを引く。描く数は計算シェーダーが引数バッファに書く。
- 塊の選び方は「まとまりごとの独立判定＋ヒステリシス」だけにする。Omni の古い方式(Chained)は作らない。
- 要求(どのページが要るか)は計算シェーダーで作る。画素シェーダーから書くと、深度を画素シェーダーが書く作り(ADR-0084)のため、隠れた画素を早めに捨てられなくなる。
- 遮蔽の判定(Hi-Z)は、物理距離の画像(`SceneDistance`)の最大値を粗くしたものを使う。対数の深度の符号化に依存しない。
- 選択は最初から複数の視点に対応する。主ビュー、影、AO と Lumen の前処理を同じ選択で描く。影を代理メッシュで描くと、主ビューの形とずれて縞が出るため。

### 4. 三角形の下限と、細部の法線マップ
ユーザーの提案(2026-11-16)。Omni には無い。採用の基準は「負荷が大幅に減り、劣化がわずかなら採用」。
- 塊を細かくするのを、三角形が画面で一定の大きさ(例 16 画素)より小さくなる手前で止める。それより細かい凹凸は法線マップで表す。
- 本エンジンで特に効く理由: 画素シェーダーが重く、隠れた画素を早めに捨てられない。GPU は三角形 1 枚ごとに 2×2 画素の単位で計算するので、小さい三角形ほど無駄が増える。
- メッシュは、前処理で原本の細かい形から「物体の向きで記録した法線マップ」を焼く。どの粗さの塊からも同じ画像を引けるので、粗さが切り替わっても陰影が変わらない。重ならない UV があることが条件。
- 地形は、標高タイルの細かい階層から画素ごとに法線を求める。
- 輪郭と影の形は粗いままになる。16 画素は仮の値で、品質設定ごとの値と既定は計測で決める(M0130)。

### 5. 仮想シャドウは作り直す
- M0115 の実装を置き換える。並行する経路は残さない。計画は L4 へ移し、L0 は実行だけにする。
- Omni の数値を使う: 16 段、1 段は 128×128 ページ、置き場は 8192×8192。
- 画面からのページ要求、粗いページの同時要求、Q64.64 のカメラ位置に固定した格子、VG の塊を同じ選択でページへ描く(Omni に無い接続)。
- 無効化は「動いた物」の印で決める。実行時はカメラが描画空間の原点で、物体の行列はカメラが動くたびに変わるので、行列の比較は使えない。印は Q64.64 の変換を持つ L5 が出す。
- 既存の柔らかい影(ADR-0083)は維持する。影の既定はカスケード影のままにし、仮想シャドウは `DirectionalShadowRendering` で選ぶ。局所光は範囲外。

### 6. VirtualObject は ECS の部品にする
- 親が画面上の大きさを測って段を選び、子が段になる。子は `Parent<T>` で親の段を読み、自分の表示を切り替える。子から親へは書けないので、「準備完了」はエンジンのサービス経由で伝える。
- 約束は Omni と同じ: 画素だけで決める、ヒステリシス 1.25、新しい段を出してから古い段を消す、準備できた段へだけ上がる、失敗したら今の段を描き続ける。

### 7. 地形と仮想テクスチャ
- 地形は平面と球。マスの四分木を Q64.64 で選び、マスの格子を VG の「形」として同じ描画経路へ流す。
- 巨大な素材(NASA の標高と画像)は、前処理でタイルの階層に分けて必要な分だけ読む。入力はメモリに全部載せず、少しずつ読む。Unity 側にあった容量の制限は考えない(ユーザーの判断。素材は最高画質のまま扱う)。
- タイルの置き場は「索引 1 つ＋まとめファイル」にする。1 タイル 1 ファイルにすると数百万件になるため。
- マスのキー(面・階層・x・y)を、高さタイル・色タイル・RVT の合成ページの番地として共有する。
- 仮想テクスチャの対象は「位置から番地が決まる面」(地形と、上から貼る合成)にする。UV で貼る一般のメッシュは範囲外。

### 8. 置き場所と利用者の書き方
- 描画本体はエンジン本体に置く(ADR-0079。描画のパスと計算シェーダーはプラグインに置けない)。計画は `src/Engine/Rendering`(L4)、D3D12 の実行は `src/Windows/Graphics`(L0)、成果物の形式は `src/Engine/Content`(L6)、前処理は `src/Cooking` と `tools/Cge`(L7)。描画用の新しい csproj は作らない(ADR-0087、ADR-0099)。
- 利用者は VG のために Component を書かない。素材の取り込み設定で有効にするだけで、`StaticMesh` はそのまま使う。
- メッシュの簡略化は自前の C# で作る。「エンジン所有の実装を正しさの基準にする」決まり(`Docs/Architecture.md` の External provider boundary)による。Omni が使う外部ライブラリは、Omni 側にも元のソースが無い。

### 9. 段階
| 段階 | 目的 | 主な確認 |
|---|---|---|
| M0129 共通の下回り | 従来メッシュを GPU シーンへ載せ替える。共通部品を作る | ゴールデン 7 枚が変わらない |
| M0130 VG のビルドと描画 | メッシュを塊の階層にし、全部読み込んだ状態で描く。影にも落とす | 原本メッシュとの画像の差 |
| M0131 VG の遮蔽判定と読み込み | 隠れた塊を描かない。必要なページだけ読み込む | 見える物が消えない |
| M0132 仮想シャドウの作り直し | M0115 を置き換える | カメラ移動でページを使い回せる |
| M0133 VirtualObject | 段の切り替え | 自動試験で完結 |
| M0134 タイルの前処理と地形 | NASA 素材のタイル化、平面と球の地形 | 月の実データ |
| M0135 RVT と統合検証 | 地形の層の合成、統合の検証シーン | 原本との差を測る |

## 採らなかった案
- **目標文書を改めて正式な目標にする**: ユーザーが「公開後の作業の前倒し」を選んだ。
- **1 つの仮想ページの仕組みを 3 つの使い手で共有する**: 使い手ごとにページ表とキーの形が違い、最初から一般化すると過剰になる(決定 1)。
- **材質ごとに間接描画を分ける**(Omni の方式): 視点×材質の区画と出力位置の割り当てが要る。番号引きならどちらも要らない。
- **VG だけ別の材質経路にする**: 並行する経路になる。従来メッシュも同じ GPU シーンに載せる(決定 2)。
- **深度プリパスを足す**: 深度が一致する画素だけ描く判定は、画素シェーダーが深度を書く作りと相性が悪く、ADR-0085 の範囲に踏み込む。

## 帰結
- ABI は `stage-v17`(物体と材質の表)、`stage-v18`(番号引きの配列、環境の表)になる。生成物は区分 C(ADR-0098 §5)なので、古い成果物は拒否して作り直す。
- 必要な GPU の条件が上がる(リソース束縛の段 2 以上)。
- M0115 の仮想シャドウの読み手と計画は M0132 で消える。ADR-0082 は M0132 の ADR で置き換える。
- 従来の描画経路(1 物体 1 命令)は M0129 で無くなる。物体を描く入口 9 か所(主パス、カメラプレビュー、DDGI、AO の前描き、影の比較、Lumen の前処理とカード、影アトラス、仮想影ページ)を同じ変更で載せ替える。

## 検証
- 関門(M0129 単位 1): 計算シェーダーが書いた数での間接描画、頂点バッファなしの頂点取得、上限なしのテクスチャ配列の番号引きが、WARP と実機(2026-11-17、リソース束縛の段 2 以上)の両方で画素まで一致した(`tests/Windowsのテスト/Windows/Graphics/GpuDrivenDrawGateTests.cs`)。
- 各段階の確認は上の表のとおり。WARP の時間は性能の根拠にしない。性能と常駐量は実機で測る。
- 見た目が変わる段階は、修正前と修正後の実画像を同じ条件で保存して並べる。

## 関連する機能
- 既存: F-L4-020(仮想方向光シャドウ。M0132 で置き換える)、F-L4-006(可視性・LOD)、F-L4-008(非同期アセットハンドル)、F-L5-037(World Cell のストリーミング)。
- 新しい機能 ID は、各段階で機能台帳へ登録する直前に採番する。

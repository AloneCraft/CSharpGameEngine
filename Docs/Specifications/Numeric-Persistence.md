# 数値型から独立した数値保存

## 現在の実装範囲

`NumericValueCodec` は有限数値の保存境界である。64/128/192bit固定小数点、float、doubleを共通形式へ書き、任意の対応する数値設定へ最近接・偶数丸めで読む。計算ランタイムの型を切り替える機能ではない。

`LogicalScalar.ToCanonicalBytes` / `TryReadCanonical` は既存Q64.64および追加の [数値設定](Numeric-Configuration.md) とこの形式を接続する。WorldCellはv2でこの境界を使い、従来のv1も読み込む（[World Cell仕様](World-Scale-Runtime.md#world-cell-artifacts)、[ADR-0094](../Decisions/ADR-0094-WorldCell-Numeric-Values.md)）。Scalar単体の生の読み書きは選択した幅を使い、既定型の16バイト形式は維持する。生成WorldのSnapshotもv2で共通の実数識別と正確な保存文字列を使い、確定できるv1構造を静的に移行する（[Snapshot契約](Ecs-Runtime.md#snapshot-artifact)、[ADR-0095](../Decisions/ADR-0095-Profile-Neutral-Snapshots.md)）。

## 共通バイナリ v1

すべてリトルエンディアン。値は `sign * (integer + fraction / 2^fractionBits)`。

| 項目 | 格納 |
|---|---|
| 形式識別 | ASCII `CGN1`、4バイト |
| 符号 | 1バイト。0は正、1は負 |
| 小数部のビット数 | UInt16 |
| 整数部のバイト数 | UInt16 |
| 整数部 | 符号なし、可変長。上位のゼロバイトは除く |
| 小数部 | 符号なし、`ceil(fractionBits/8)`バイト |

小数分子の末尾のゼロビットと分母の2を約分する。小数がなければ小数ビット数は0。整数の0は長さ0。0の符号は正。同じ数値の符号化は元の型にかかわらず同一になる。

整数部は最大128バイト、小数部は最大1074ビット。doubleの有限値と最小の非ゼロ値、およびすべての対応固定小数点値を扱える。非正規表現、余分なバイト、切り詰め、未知形式、非有限値は拒否する。破損の検査には外側コンテナーのチェックサムも必要で、この数値形式自体はチェックサムを持たない。

## 読み込みとテキスト

- 固定小数点入力は符号付き2の補数8/16/24バイト。小数ビット数は0から総ビット数−2。
- 固定小数点、float、doubleへの復元は最近接・偶数丸め。丸めた結果が範囲外なら失敗する。出力バッファは成功時だけ更新する。
- 非ゼロの負数が丸めで0になる場合も、保存境界では正の0に正規化する。
- `ToText` は保存値を正確な有限10進小数で書く。float/double向けの短い表示文字列ではない。
- `TryReadCanonicalText` はその保存文字列を丸めずにCGN1へ戻す。読み先の幅・精度を参照せず、元の正規性を検査する。冗長な符号・0・小数末尾、空白、指数、非有限値、共通形式の範囲外を拒否する。入力用の短い `0.1` は正確な2進数の保存表現ではないため、この入口では拒否し、入力には下記のTryReadFixedTextなどを使う。
- `TryReadFixedText` は最大4096文字の符号・数字・小数点を読み、doubleを経由せず固定小数点へ丸める。空白、桁区切り、指数表記はこの入口では受け付けない。
- 一時的な `BigInteger` は外部数値表現との変換メソッド内だけで使う。シミュレーションの計算型や保存されるオブジェクトのフィールドには使わない。

## 残る接続

Fixed/Float/DoubleのSource・SDKビルドと、対応する値型のSnapshot静的生成は実装済み。WorldCellとSnapshotはv2の共通保存へ移行した。実際の別設定のWorldで、同値の保存一致、読み先の精度への丸め、後続要素の範囲外でも状態を部分変更しないことを検証する。設定画面、素材生成物だけを使う実行、制作から配布までの通し検証は別の残作業である。

# Asset Editors

- Intended status: Specified
- Decision: ADR-0089、スケルタルの読み込みは ADR-0090
- Feature: F-L8-036、関連 F-L8-035
- Milestone: M0127

UE5 のアセットエディターに倣い、アセットをダブルクリックすると種類別の専用ウィンドウが開く。ウィンドウは VS のドキュメントウィンドウで、既定は前面のフローティング、ドッキングもできる。
範囲は **現在 C# Game Engine が実装している機能だけ**。実装のない UE5 のエディターは作らない（下の「対象外」）。

## ウィンドウ

- 登録: 1 つの `AssetEditorFactory` が `AssetEditorRegistry` の表にある拡張子を担当する。表にない拡張子は辞退する。優先度は VS 標準の JSON エディター・画像エディターより高い。
  表は `AssetWorkspaceClassification`（Contracts）の分類とテストで照合する。シーン JSON とシェーダーグラフは別のエディターが担当する。
- 開く場所: Tools > Options > C# Game Engine > Asset Editors の「フローティング（既定）／ドキュメントタブ」。
  フローティングはフレームが最初に表示されたときの一度だけ。ユーザーがドッキングしたウィンドウを再表示で浮かせ直さない。
  VS の復元・プログラムからの「指定のエディターで開く」（`CEF_OPENSPECIFIC`）では保存されたレイアウトを尊重し、フロート化も位置決めもしない。
  浮かせた直後に約 1.2 秒遅らせて、メイン画面の 85%（最大 1280×800、最小 640×480）を中央に置く。API の事実は ADR-0089。
- 共通の枠（`AssetEditorShell`）: 上にツールバー（Solution Explorer で表示 / Assets で表示、種類ごとの項目）、中央に表示領域、右に Details（Inspector と同じ経路）、下にステータスと進行表示。境界は GridSplitter。
- 浮動中はウィンドウの所有者をVS本体に設定し、VS本体を操作してもその背後へ隠れない。表示・ドッキング先の変更・復元で所有関係を更新する。ドッキング時はVS本体の所有関係を変更しない。別アプリよりも常に上に置くシステム全体のTopmostや、定期的な前面化は使わない。
- 2 つのボタンは、対象が読み込み済みのプロジェクト（Assets は登録済みの一覧）にあるときだけ有効で、ないときは無効にして理由をツールチップに出す（表示・再表示のたびに判定し、Assets が一度も開かれていない間は押せる）。「ソリューション エクスプローラーで表示」は、読み込み済みのプロジェクトに属する対象ファイルの親を展開して選択する。Assetsへの登録を前提にしない。「Assets で表示」は、登録済みの対象のプロジェクト・フォルダーへ移動し、名前・種類・提供元・状態のフィルターを解除して対象を選択・スクロールする。場所固定と詳細表示の設定は維持する。対象外・準備中・失敗は共通ステータス欄に理由を表示し、ファイルを自動でプロジェクトへ追加しない。
  VSの「その他のファイル」への所属（`DOCINPROJ_DocInExtFilesProject`）は、読み込み済みのプロジェクトへの所属に含めない。`DOCINPROJ_DocInProject`の場合だけSolution Explorerへの選択を実行する。
- キーボード: 描画面は Win32 フォーカスを持たない（ADR-0041）。F=フレーム、Space=再生/停止（音声）などのショートカットは WPF のフォーカスから受ける。
- 再読み込みと状態: 文書の名前変更後は、共通ツールバーのSolution Explorer／Assetsへの移動も現在のパスを使う。VSの明示的な文書再読み込みは、パスが同じでも各エディターの再読み込み処理を実行する。画像は再読み込み中・失敗時に旧画像を表示せず、音声は旧ファイルの要約時間をリセットする。内容の生成中に出たステータスは共通枠の接続時にも引き継ぐ。
- データアセットの保存ボタンは開いている文書の保存処理に委ねる。文書が見つからない、または保存に対応していない場合は失敗理由を表示し、保存成功とは表示しない。
- データアセットの表示側は VS の文書表の名前変更通知を追跡し、自分の文書が変更された場合に詳細欄やツールバーの参照先を新しいパスに更新する。文書の保存・Undo は共有テキストバッファーが引き続き担当する。

## 種類別のエディター

Assetsの「作成 > Graph」は、同梱されたStageテンプレートを依存サブグラフと一緒に生成する。Add New Itemと同じID再割り当てを使い、依存ファイル名にはルート名を付ける。まずメモリー上で一式を計画し、循環参照・欠落・ID不一致を拒否する。作成先の既存ファイル・サイドカー・プロジェクト外のパスを拒否した後、依存ファイル、ルートの順で作成する。一式は既存の物理操作ジャーナルと1つのネイティブUndo取引に載せ、途中の失敗では記録済みの操作をキャンセルする。クラッシュ／電源断時の復旧はM0123の個別操作ジャーナルの保証範囲に従い、一式のファイルシステム原子性は保証しない。

| UE5 相当 | 拡張子 | 機能 |
|---|---|---|
| Static Mesh Editor | `.glb` `.gltf` `.fbx` | 3D ビューポート、表示モード（Lit / BaseColor / Normal / Wireframe）、頂点・三角形・サイズ、プレビューレベル選択と管理、Details（取り込み設定・再取り込み・メタデータ）。静的 glTF はホストでテクスチャ付き PBR を読み込む。FBX は取り込みブリッジの形状のみでテクスチャなし |
| Skeletal Mesh / Skeleton | スキンを正確に 1 つ持つ `.glb` `.gltf` | Static Mesh の機能に加えて、ホストが読み込んだスキン付きメッシュ（テクスチャ付き PBR）の表示、Skeleton のツリー（関節名と親子）、ボーンの線の表示切り替え、選択したジョイントの強調 |
| Animation Sequence | アニメーションを持つ `.glb` `.gltf` | クリップの選択、再生・一時停止（Space）、スクラブ、ループ、速度（0.25〜2 倍）、時刻の表示。スキンを持たないアニメーションだけのファイルは、プロジェクト内のスキン付きメッシュから「プレビューするメッシュ」を選ぶ（選択はセッション内だけで、ソースには書かない） |
| Texture Editor | `.png` `.jpg` `.jpeg`（`.dds` `.tga` `.hdr` `.exr` はデコーダー未対応と表示） | 拡大縮小（全体／100%／ホイール）とパン、RGBA/RGB/R/G/B/A のチャンネル表示、アルファの市松模様、寸法とファイルサイズ、Details。デコードは L7 Cook ワーカーが作る派生 PNG（最大 2048 px）だけで行う |
| Sound Wave Editor | `.wav`（`.ogg` `.mp3` `.flac` は再生のみで「ゲームでは読めない形式」と表示） | 波形（ピーク）と再生位置（クリックでシーク）、再生・停止・ループ、サンプルレート・チャンネル・ビット深度・長さ。形式と波形はアセット作成ブリッジがゲームと同じ `WavReader` で読んだ要約 |
| Font Editor | `.cgefont` `.ttf` `.otf` | `.cgefont` は焼いた SDF アトラスの表示と寸法・グリフ数。`.ttf`/`.otf` は見本文字。焼き込み設定は Details。編集は FontBaker の範囲で、確認のみ |
| Data Asset Editor | `.cgeasset` | 型に従った値編集（Details、ライブバッファ）、「JSON で開く」。保存・dirty・Undo は VS のテキストバッファーが持つ |
| Material Editor | `.cgeshadergraph` `.cgesubgraph` | 既存のシェーダーグラフエディターを既定フローティングで開く |

静的 glTF の頂点・三角形数は、複数ノードが同一プリミティブを参照しても、そのプリミティブを一度だけ数える。スキンがなくメッシュとアニメーションを両方持つファイルは静的な初期姿勢として表示する。

### スケルタルとアニメーション（ADR-0090）

- VSIX は glTF を読み込まない。glb の JSON チャンクだけを見て（`GltfSkeletalProbe`）、スキンが 1 つなら Skeletal Mesh、スキンがなくアニメーションがあれば Animation Sequence、スキンが 2 つ以上なら静的な形状だけを表示して理由を示す。
- 実際の読み込みと姿勢の評価はプレビューホストが行う。メッシュ・マテリアルの変換はゲームと同じソース（`StageGltfAssets`）、姿勢はゲームと同じ `Skeleton` / `AnimationClip` なので、プレビューとゲームで差が出ない。
- 初回のフレーミング・床・照明には、ホストがスキンと剛体ノードから計算したレスト姿勢の境界を使う。先頭プリミティブだけの事前読み込みには依存しない。境界はアニメーションの全姿勢を含むとは限らない。
- ホストの応答がジョイントとクリップの要約を返し、エディターがツリーとクリップ一覧を作る。再生は時刻を進めてホストへ送る（クリップ番号・時刻・ループ）。クリップが選んだメッシュのどの関節も動かさない場合は理由を示し、バインド姿勢で表示する。
- プレビューメッシュの変更や文書の再読み込み時には、古いツリー・クリップ・再生状態を消し、新しい要約の読み込みが成功してから表示する。読み込み失敗時に前のメッシュの情報を残さない。
- 選んだメッシュのスケルトンとジョイント名が一致するクリップだけが評価される。骨の色は通常が黄、選択したジョイントに入る骨と出る骨が水色。
- プレビューレベルの床が変わって描画サーバーを置き換える場合も、同じメッシュとアニメーションの読み込み済みデータ・姿勢を再利用する。床の有無によるメッシュ番号の変化を補正し、ソースやテクスチャを読み直さない。ファイルの明示的な再読み込みはセッションを作り直す。
- VSが文書を名前変更した場合は、その文書自身へのメッシュ／クリップ参照を新しいパスへ付け替える。アニメーションだけの文書に選んだ別のプレビューメッシュは維持する。

### 3D ビューポートの操作

左／右ドラッグ=オービット、中ドラッグ／Shift+左ドラッグ=パン、Ctrl+左ドラッグ／ホイール=ドリー、F／「フレーム」=対象に合わせて初期位置へ戻す。
数式は Scene View と共有（`SceneViewState`、反転設定も同じ）。一度に反映する量は上限を持つ。

ネイティブ描画面のサイズ変更通知では、最新サイズを記録するだけにする。ホストへのResize要求は描画tickの例外処理内で適用し、連続通知をまとめる。描画ホストの障害をWin32のウィンドウプロシージャへ漏らさず、既存の復旧・エラー表示へ渡す。破棄時は保留中のサイズ変更を破棄する。

## プレビューレベル（M0127）

ツールバーの「プレビューレベル」で背景・環境・ライト・床・初期カメラを切り替える。対象のアセットはテンプレートに書かず、実行時に足す。

- 切り替えでモデルを読み直さず、カメラも維持する。カメラを初期値へ戻すのは「フレーム」だけで、そのときテンプレートの初期カメラ（方向・視野角・投影方式）を使う。
- 標準: **Default**（従来の見た目）、**Studio**（キー・フィル・リムの 3 灯と影が落ちる床、ニュートラルな背景）、**Outdoor**（太陽・大気・地面と影）、**Neutral**（中間グレーの背景、柔らかな 1 灯、影・床なし。Unlit 表示モードとは別）。標準は保護される。
- Outdoor の床は半径の 1000 倍まで広げ、遠方クリップ面もその床の対角まで伸ばす（近クリップ面は遠方に比例するのでモデルとの比率は変わらない）。空は地平線の下に何も描かないため、床が地平線より手前で終わると黒い帯が出る。低い視点で床の端が地平線に接することは WARP の描画テストで確かめている。
- ユーザーのテンプレートは `Assets\PreviewLevels\*.cgepreview`（JSON）。「管理…」で 新規・複製・名前変更・保存・削除・既定にする。新規は Default の初期値から作る。標準はコピーして変更する。ファイルを直接編集した場合は自動で反映する（使用中のファイルが壊れた場合は組み込み Default に戻し、理由を表示する）。
- 項目: 方向／点／スポットライト（4／8／8 灯まで。強さは lux・lm、範囲は m、円錐は全角度、色は線形）、アンビエント、背景（レンダラー既定・単色）、大気とスカイライト、床（大きさ・色・粗さ・グリッド）、影、露出・トーンマップ・ブルーム・AO、初期カメラ。局所ライトの光束は対象の半径の2乗に比例する。
- 空の背景には既存の物理大気を使う。画像キューブマップを指定する skybox は現在のプレビューにはない。
- 選択は プロジェクトごとに 最後に使った項目と既定を保存し、次回開いたときに復元する。起動時に選択済み項目が欠落・破損していた場合は理由を表示し、次の有効な既定候補、または組み込み Default を使う。表示中の項目が欠落・破損したときと、ホストが環境を適用できないときは組み込み Default へ戻して理由を表示する。
- ReadyとDefaultへの縮退成功は、ホストのOpenに加え、最初の照明・フレーム適用と描画が成功してから通知する。Default自身の読み込みに失敗した場合は成功通知を出さず、その失敗診断を保持する。停止後にユーザーが別のテンプレートを選んだ場合は、明示的な再読み込みとして再試行できる。輸送障害に対する自動の描画面再生成は1回までとし、テンプレート変更による回避とは区別する。
- 各ウィンドウは独立した RenderServer を持つ。ライトは他のプレビュー・シーンのビューポート・ゲームのレベルへ漏れない。
- 既存のシーン JSON はテンプレートにしない（ADR-0089 §4）。

## 対象外（実装がないため作らない）

- マテリアル単体アセット（ソース形式がない）、Niagara、Physics Asset（Ragdoll）、入力アクションのエディター
- ナビメッシュ・破砕・物理キャッシュなどのベイク生成物のエディター
- 複数のスキンを持つ glTF の表示、ブレンドスペース・IK・ステートマシンなどの再生（ランタイムの Animator の範囲で、ビューアは単一クリップの再生のみ）
- 波形の編集・加工、フォントの焼き直し（外部ツールまたは FontBaker の範囲）

## 受け入れ条件

- スキン付き `.glb` で Skeleton のツリーとボーンが出て、アニメーションを選ぶと再生され、スクラブで姿勢が変わる。アニメーションだけの `.glb` はスキン付きメッシュを選んで再生できる。
- 各種類の拡張子でダブルクリックすると VS の前面にフローティングで開く。シーンは中央。ドッキング後の再アクティブ化で浮かない。設定を「ドキュメントタブ」にするとタブで開く。
- VS を閉じるときに開いていたウィンドウは、再起動で保存した位置に復元され、中央へ戻されず、全面が描画される。
- テンプレートの切り替えでモデルとカメラが維持される。標準の 4 種が描画できる。ほかのウィンドウにライトが漏れない。
- 高コントラスト・DPI の組み合わせの実機確認は M0127 の未確認項目。

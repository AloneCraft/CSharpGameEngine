# 数値設定に応じた角度の表示と保存

## 観測
Double設定の確認用シーンで位置の編集・保存後に壁のずれを観測した。保存済みシーンと元テンプレートの回転値にはラジアンと回転数に相当する差が多数あり、差がどの保存操作で生じたかは未特定。Double角度の書き出しで回転数へ変換しない問題はテストで再現した。0.1.18では位置の入力自体は成功したが、シーン全体の保存は未完成。Inspectorの表示は固定値とDouble値を角度変換より先に処理し、固定値の角度入力には対応する分岐がなく、Doubleの角度入力も単精度専用処理に拒否される。ユーザーは以前から角度表示の不具合を観測している。

回転は `Rotation.EulerRuf.R` のように入れ子になる。従来の編集処理は直下のRUF成分しか更新できず、表示行も深い角度を編集可能にしていなかった。存在するメンバーと一意に解決できるコンストラクター引数をたどって更新する修正と、度入力から保存・再読込までのテストを追加した。確認用VSではDoubleの45度を入力・保存し、再起動後も45度と表示されることを確認した。

## 方針
ゲーム内の値はプロジェクトが選択するLogicalScalarを正とする。Float/Double設定時はそれぞれ選択された実体型を使い、固定64/128/192bitでは指定された小数位置を維持する。エディター・ビルドツールは異なるランタイムと複数の設定を扱うため、対象プロジェクトの型やメタデータと文字列表現を静的に読み、設定に沿った範囲検査・丸めを行う。固定小数点をfloat/doubleに経由させない。角度は既存契約どおりJSONには回転数、Inspectorには度、ゲーム内には宣言された単位で扱う。πは有限精度の定数であるため、設定された型の範囲と丸めに合わせ、変換されない他の値は書換えない。修正前後に型や単位の変更がない位置・角度を失わないことを検証する。

## 受け入れ
- Float、Double、固定64/128/192と小数位置に対し、0・90・-180度、境界と高精度の表示・入力・保存・再読込をテストする。
- 角度以外の編集時、他の回転値と配置が元のJSONのまま維持されることを実際のコミット処理で確認する。
- ThirdPerson実シーンで読み込み、位置編集、保存、再表示、ゲーム起動を行い、編集前後の壁形状を実画像で比較する。
- SDKとVSIXのバージョン、仕様、テストを一致させ、型やプロジェクト設定の実行時探索、動的コード生成へのフォールバックを導入しない。

関連テストとDoubleの実画面確認は成功した。全数値設定での実画面操作とゲーム起動までの一巡は未確認。

# ThirdPerson ステージの壁とプレビュー座標の整合

## 背景
UE から取り込んだ ThirdPerson の壁がシーン表示で床の外へ伸びる。ユーザーは配置の修正と実画像の前後比較を要求している。

## 現状の観察
ゲームは `ModelAssetBundle` の正規化済み形状を使う。一方 `MeshLoader` は単一プリミティブ用の旧 glTF ブリッジを呼び、glTF の Z の向きを保ったまま描画する。壁の立方体は原点を中心とせず、各軸の 0..1 にある。例えば SM_Cube2 の F=20、F scale=40 は正規化後の Z=-1..0 と組み合わせると -20..20 になるが、旧経路では 20..60 になる。

## 過去設計から引き継ぐ仕様
`20261031-static-production-flow.md`、ADR-0097 の共通モデル成果物を使う。VS 本体へソース解析器を読み込まない。シーンの配置値、原点、UE エクスポート済みデータを補正値で変更しない。

## 目的
シーンとサムネイルがゲームと同じ正規化済み形状を使い、壁の位置、回転、選択範囲が一致する。

## 非目的
ゲームルール、ステージ配置、シリアライズ形式を変更しない。スキニングやプレビューのテクスチャ対応を追加しない。

## 提案設計
既存の AssetAuthoring worker でモデルを準備し、指定した成果物ハッシュを確認して CPU 描画 DTO へ投影する。階層のローカル行列とサブメッシュの材質を保持する。VSIX は DTO を描画・選択用形状へ変換する。シーン内のモデルはまとめて準備し、同じソースをノードごとにコンパイルしない。FBX とプロジェクト外の生成プリミティブの既存経路は変更対象に含めない。

## 影響範囲
L7 AssetAuthoring worker、L8 MeshLoader / シーン描画 / サムネイル、対応する既存テスト。F-L8-036 と M0128 のプレビュー整合性。

## 移行手順
実アセットで旧経路の壁範囲を再現する。共通成果物経路を実装し、同じ配置で床の境界に戻ることを確認する。前後画像は同じカメラで生成し、撮影方法を記録する。

## テスト計画
実 ThirdPerson の片側原点キューブ、四分の一回転、階層、複数材質、ハッシュ不一致、ソース削除後の成果物読込みを確認する。既存の描画 DTO / 選択 / プレビュー試験を再利用する。

## リスクと対策
冷間読み込みの回数増加をまとめた準備で防ぐ。失敗時は診断を返し、古い生 glTF 経路へ黙って戻さない。描画とフレーム更新で同じ部品 ID を使う。

## 未決事項
なし。実際の検証結果と残る制約は同文書へ追記する。

## 合意状態
ユーザーの修正指示と、既に実装を承認された共通成果物方針の範囲内で実施する。

## 検証結果
`ThirdPersonPreviewGeometryTests` は実テンプレートの8モデルと54描画オブジェクトを使用する。旧読み込みで片側キューブの Z=0..1、共通成果物で Z=-1..0 を確認した。SM_Cube2 は同じ配置値で F=-20..20 になる。ソース削除後の読込みとハッシュ差し替えの拒否も確認した。ワーカー関連15件が合格。

`SceneModelRenderObjectBuilderTests.JsonQuarterTurnPreservesTheImportedWallDirection` は float と128bit固定値の両方でJSONから四分の一回転を読み、横壁の方向を確認する。`RenderPreviewSceneBuilderTests` は階層変換・複数材質・選択とフレーム更新の同じ部品IDを確認する。Release全体は1596件成功した。

全体試験が起動したテンプレート参照のビルドで出力競合を再現したため、既存 `TemplateSceneEditingTests` の子MSBuildを `-m:1 -nr:false -p:UseSharedCompilation=false` に統一した。失敗時の1593成功/3失敗を保存し、修正後は該当3件を含む全1596件が成功した。競合を隠す再試行は追加しない。

`.artifacts/StaticProduction/wall-preview-20261104/` に前後の実描画・入力DTO・カメラを保存した。修正前は旧読み込みを再実行したもので、VSの画面写真ではない。両方900×900、同一カメラ、同じ配置、WARP、54描画オブジェクト、D3D12エラー0件。シーン補助表示やVSの枠は含めない。並列表示は `comparison.html`。検証ジョブ `4373d80db2ae406d8ae0924b171fd223`（ワーカー15成功）、`eb6e64034d9f42bcac7cc4ad557f66f8`（修正後6成功、全1596成功、前後描画、数値出力Debug/Release各3成功、SDK45梱包、VSIX梱包関連52成功）を参照する。

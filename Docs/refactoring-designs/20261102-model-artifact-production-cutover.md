# モデル生成物を使う制作・実行・配布の接続

## 承認範囲

ユーザー承認済みの [静的構成と制作フロー](20261031-static-production-flow.md) のモデル生成物への切替を具体化する。ADR-0080の実行時境界を引き継ぎ、元データのデコードはCookワーカーで行う。新しいsrcプロジェクトや、実行時の元データ読込への切替は追加しない。

## 現在の観測

- ModelArtifactPreparation、ModelContentCompiler、ModelContentIndex、ModelRuntimeCodecsとCASは実装済み。
- 通常のMaterialを含むIRは、用意したMaterial生成物をModelArtifactPreparationへ渡す必要がある。現在のCLI compileはそのResourcesを渡さない。
- 現在のCLI compileは一つの入力だけをModelContentCompiler.CompileAsyncへ渡す。プロジェクトで各ファイルを個別に呼ぶと、全入力集合として公開するindexを保てない。
- 切替前はStageSceneDataBuilder、StageGltfAssets、SkeletalAssetCache、静的・骨格プレビューが元のglTFと画像を読んでいた。現在はStageModelAssetsとModelAssetBundleへ切替中で、切替後の検証を必要とする。
- 既存SDKはモデルの共通生成物を実行側の必須入力として配布していない。

## 設計

1. ワーカーの正規化済みIRから、MaterialとTextureの共通生成物を前処理する。既存のMaterial/Textureの形式・参照・画像処理を再利用し、Model/Mesh/Skeleton/Clip/Licenseと同じ厳密な依存関係へ入れる。元データ・画像のデコードをゲームやPreview Hostへ残さない。
2. プロジェクトの全対象ソースを一回の操作として取り込み、同じ入力集合から一つのindexとCAS閉包を公開する。既存の増分コンパイラーを再実装しない。入力一覧・設定・メタデータ・キャンセル・前回成功時の状態を検証してから公開する。別の資産を取り込んだ結果、他の資産のindexが消えないことを不変条件にする。
3. Contentの既存RuntimeAssetStoreと閉じたcodec集合で、モデルの厳密な参照・ハッシュ・依存閉包を読み込む。ソースURIは保存済みモデルの選択にだけ使い、ファイルをデコードするためには使わない。欠落・破損は明示的な読込失敗にする。
4. ゲームとプレビューで同じStageモデル変換を共有する。既存の頂点・三角形・法線・接線・UV・配置・マテリアル・骨格の順序・静止姿勢・アニメーションの意味を維持する。スキニング対象のメッシュとパレットの対応も一つのデータから作る。
5. Source・SDKのMSBuildから生成を実行し、Navigationなどの調理より前に完了させる。作成ツールとワーカーは制作側へ置き、配布物には必要なindex・CAS閉包・シェーダーなどを含める。ゲームのImport/SharpGLTF/Assimp/Cooking依存と、置き換えた旧読込コードを同じ切替で外す。
6. プレビューを開く・更新する操作は、制作側の共通生成処理へ接続してから生成物を渡す。プレビュー自身が取り込みを所有しない。失敗した再取り込みは直前の成功した表示・生成物を破壊しない。

## 変更前の比較対象

切替前のデコード結果を試験の比較対象として保存し、単純な静的モデル、階層、反転を含む変換、複数マテリアル、Mannyの骨格・スキン・クリップを確認する。共有ライブラリを変換だけのために実行側へ残す互換ブリッジは作らない。最終的な旧読み方の削除前に、独立した位置・姿勢・材質と描画の比較を通す。

## 検証と受け入れ

- 複数資産の増分生成、変更なしの再生成、失敗・取消時の前回成功の維持、厳密な依存関係、破損・欠落の拒否。
- ゲーム・静的プレビュー・骨格プレビューが同じ生成物と配置を使うこと。元のモデル・画像を取り除いた後も読込・描画できること。
- Source・SDKで三人称の歩行・ジャンプ・保存再開を確認し、他テンプレートも回帰確認する。
- 配布物を開発環境に依存せず起動し、必要な依存関係だけを含むことを確認する。
- 実装・試験の結果から仕様、台帳、Reverse、Conformance、M0128、Changelogを同期する。基盤や単体試験だけで制作全体を完了扱いしない。

## 状態

部分実装。組み込みglTF取り込み器、材質・画像生成ワーカー、プロジェクト一括CLI、失敗時の前回生成物を含むコンパイル結果は接続済み。glTFの座標正規化は共通処理が所有する。親CLIはソースSDKを読み込まず、材質・画像の生成も既存のCookワーカー契約を通す。テンプレートの床のグリッドは材質生成物へ保存し、従来のグリッドなし材質形式も読む。

実行・プレビュー・ナビメッシュ・距離場を共通生成物へ切り替え、旧ゲーム読込を削除した。protocol 14の制作ワーカーと本体、Source/SDKの4テンプレートと数値設定を検証した。モデル本体・配布用一覧・ファイル編集の復旧記録を、ソース生成器のJSON契約と閉じたモデル型一覧へ移した。型検索無効のContent全71件、旧30モデルの読込、別プロセスのFloat→Double保存再開、自己完結配布物のWARP110フレームが成功した。通常版SDK0.1.40とVSIX0.1.11を作成し、VSIX全1565件はReleaseで成功。Windows関連123件はDebugで成功し、実行中の正確な数値編集・モデルの参照先コピー・欠落モデルのエラー統一を加えた148件はReleaseで成功した。最終SDK0.1.42・VSIX0.1.13を梱包し、外部4テンプレートのビルド・操作実行と自己完結Double配布物の起動を検証した。残る実画面の設定・制作操作が未検証のため、M0128はPartiallyImplementedを維持する。証跡と現在の範囲はM0128に記録する。

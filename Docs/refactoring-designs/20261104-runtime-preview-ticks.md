# 実行用プレビューの更新待ちによる停止

## 背景と現状の観察
SDK46 / VSIX16 の実VSでシーン表示が失敗した。開いているVSの終了は確認待ちのため操作を追加せず、同じホストと配布物で別プロセスの表示を再現した。シーン表示はWARP・通常GPUともOpen/Update/Render/Close成功。実行用プレビューはOpen/Update成功、最初のRenderが両GPUで30秒以内に完了しない。待ち時間を増やして修正としない。

取得したスタックではRenderが `StageModelAssets.AppendMaterials` の非同期ファイル読込完了を同期的に待ち、その間に多数の周期更新 `TickEditorWorld` が同じGateのロック取得を待っていた。ファイル読込の継続処理に使う実行枠を、待機中の周期更新が消費している。根本原因候補はこの更新の積み残しで、単独ゲームの通常GPU/WARP実行は成功している。

## 過去設計から引き継ぐ仕様と目的
M0128 / ADR-0097の共通モデル成果物を使った制作表示を成立させる。ワールド更新と描画の排他、失敗時の診断、モデルの読み込み契約を維持する。実時間の周期更新は重ねて待機させず、処理中の回は実行せずに次の周期へ進む。次回の更新は既存のTickRealtimeで時刻差を処理する。

## 提案設計と影響範囲
`RenderPreviewRuntimeSession.TickEditorWorld` のみ、Gateの取得を待たない方式にする。取得できた場合だけ更新し、finallyで解放する。Render/文書更新/破棄の既存の排他は維持する。GPUやモデルの座標は変更しない。SDKのゲームコードに変更はなく、VSIX17として別版を作る。

## テスト計画と移行
同じSDK46配布物・同じモデル・同じ別プロセス接続で最初のRender完了を確認する。WARPと通常GPUの両方で実行し、元の停止スタックと比較する。既存のWindowsプレビュー試験に必要な回帰を統合する。成功後に梱包と診断付き実VSで確認する。VSの終了・再起動は現在の明示確認に従う。

## リスクと対策
周期更新の積み残しを実行しなくなる。更新は元々TickRealtimeで実時間から計算するため、同じ時刻の更新を大量に続ける必要はない。描画中の更新を並列に実行する変更はしない。モデル読込みの待ち時間延長、再試行の追加、エラーの握りつぶしは行わない。

## 非目的・未決事項・合意状態
GPUの既定選択やゲームの計算型を変更しない。未決の製品仕様はない。ユーザーが承認済みの制作フローと表示修正の範囲で、観測した停止の最小修正を検証する。検証で原因候補が否定された場合は、同じ修正を完成扱いにしない。

## 検証結果
修正前はSDK46の同じ実モデル・配布物で、WARPと通常GPUの最初のRenderが30秒以内に応答しなかった。停止時のスタックでは `StageModelAssets.AppendMaterials` のファイル読込み待ちと、Gate取得を待つ多数の周期更新を確認した。修正後は同じ条件の両GPUでOpen/Update/Render/Close成功し、描画ハッシュを取得できた（d4ab6a673dcf4fa780d9ef9886ff6243）。`GameSystemLoopEmitter` は次の周期で `State.MeasureFrameDelta` を呼ぶことも確認した。

梱包済みホストを使う `PackagedRuntimeViewTests` にモデル付きFirstPersonStageSceneの初回描画を追加し、既存の編集試験と起動・終了の準備を共有した。23件の焦点試験とRelease全1597件が成功（a5b2b0ebfbc1429f8d69487b6919ffee）。既存Windowsの実行用プレビュー9件も成功（cecda80016634c30a83f6bfd834badf7）。VSIX17は梱包済み、現在の確認用VSは16のまま。17の配置と実画面受け入れは、保存済みVSの終了・再起動の明示確認待ち。

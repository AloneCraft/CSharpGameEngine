# 静的構成と制作フローの統合

## 背景
ユーザー承認済みの計画を実装する。静的な構成を優先し、数値設定と内部配置に依存しない保存を両立する。

## 設計開始時の観察（2026-10-31）
数値実装は Q64.64 固定。Snapshot は実行時の型検索と、復元後に再保存したバイト列の完全一致に依存する。モデルの共通アーティファクトへの移行は未完了。

## 過去設計から引き継ぐ仕様
ソースが正本。CLI は Visual Studio なしで動作する。実行時は制作ツールに依存しない。読み込みは検証後にまとめて反映する。

## 目的
三人称の新規作成、素材追加、編集、実行、保存・再開、配布、開発環境なしでの起動を一巡させる。

## 非目的
新しい描画方式や未実装の高度なモデル加工を追加しない。

## 提案設計
- プロジェクト設定で Fixed(64/128/192bit と小数点位置)、Float、Double を選ぶ。既定は Fixed/128/64。
- 適用は位置とシミュレーション。選択した型で依存先までビルドし、Float は実体も float にする。
- 対数描画と Identity は数値型と独立してビルド時に選ぶ。
- Roslyn と属性から型、呼び出し、保存処理を生成する。実行時の Reflection/Expression.Compile/IL生成/dynamic への fallback は作らない。
- 数値保存は内部型と分離する。テキストと、符号・整数部・小数部・小数桁数を持つ共通バイナリを使う。
- 読み込み先に合わせて最近接・偶数丸めし、範囲外と非有限値は拒否する。保存元の破損検査を丸め後の再保存一致から分離する。
- 共通の素材生成物を編集、プレビュー、ゲーム、配布で使う。失敗した取り込みは直前の成功を破壊しない。

## 影響範囲
Numerics、World、Entities、CodeAnalysis、Runtime、Rendering、Import/Content、SDK、VSIX、テストと仕様。

## 数値実装の具体化
固定小数点の追加幅・小数位置は、内部256bitの一時型と最大8個の64bit桁を使う乗算・除算・平方根で検証する。演算中は固定長のスタック領域だけを使い、整数の独立オラクルと比較する。結果の範囲と丸めを確認してから出力を更新する。既定のQ64.64の最適化済み経路も同じ契約を満たすものとして維持し、設定別の型へ接続する。

数学関数で定数や中間値が保存型の範囲を超える設定は、ビルド時に閉じた256bitの一時型を選ぶ。粗い小数位置では数学関数の作業精度を最低32bitにし、結果を選択した型へ最近接・偶数丸めで戻す。公開する保存型は8/16/24バイトのまま。演算カーネルはこの内部4桁と最大8桁の積も扱い、型の初期化失敗と中間値の不要な範囲制限を除く。結果自体が範囲外ならTry処理はfalseと既定値を返す。定数は個別の取得時に範囲を検査する。

Float/Doubleの実体はSystem.Single/System.Doubleとする。既存の生成・変換用APIは、ビルド時の型選択とC#14の拡張メンバーで接続し、実際のコンパイル・実行で検証する。設定は依存DLLと生成物の識別・キャッシュまで一貫させ、既定のDLLを別設定として使う暗黙の切替は設けない。

## SDKでの設定の具体化
小数位置を自由に指定できるため、全設定のDLLをパッケージへ列挙する方式は採らない。既定の配布物は既存の事前ビルドDLLを使い、他の設定はパッケージ内の不変なNumerics・World・組込みCookモジュールのソースを、利用プロジェクトのobj以下で選択した設定へビルドする。DLLの名前とモジュール境界は維持し、同じ数値設定を公開型・調理データ・依存先へ適用する。パッケージ自体を書き換えない。

生成する補助プロジェクトは親のDirectory.Build.props/targetsを再帰的に取り込まず、必要な設定・参照・Analyzerだけを明示する。数値に依存しないDLLと外部ライブラリは既存の配布物を再利用する。既定のNumerics/World参照・実行時コピーを選択した出力へ置き換え、暗黙に既定型へ戻さない。成果物と中間領域は設定別に分離する。SDKの検証はリポジトリ外の利用側を対象に、実際にパッケージを復元して型・出力・調理・実行を確認する。

## シーン入力の精度と範囲
シーンJSONの固定小数点入力に残るfloat経由とQ64.64固定の範囲定数を除く。コンパイル対象のLogicalScalarが公開する定数から幅・小数位置を確定し、10進の係数と指数を整数として読み、読み先への最近接・偶数丸めと範囲を検証する。生成する値は正確な10進入力から明示的に構築し、floatへ縮めない。検査の失敗はJSONの元の位置へ報告する。

この変換は制作時の数値境界であり、固定長のシミュレーション演算へBigIntegerを入れない。単精度・倍精度のJSONリテラルはそれぞれ直接の型を維持する。既存の角度単位変換はその契約に従い、固定値の範囲検査とは分離する。Visual Studioと生成器は同じSceneModelの処理を使う。

## Snapshot移行の具体化
新形式は数値の保存形を計算型から分離し、固定小数点とSingle/Doubleを共通の実数の種類として構造の識別に使う。数値値は正確な有限10進文字列にする。元の正規な文字列・JSON・外側のハッシュを検証してから読み先へ丸め、範囲と型の検証を終えるまでWorldへ適用しない。丸め後の再保存一致を元データの破損検査へ使わない。

旧形式は既存の構造識別と読み方を維持し、新形式への明示的な移行を行う。旧構造のキーと新構造のキーの対応、値の読み書きはRoslynで閉じた表から生成する。型が消去された別ライブラリなど、旧構造を確定できない場合に推測で受け入れない。旧値を読み先へ検証・変換した新形式の文書を作ってから、通常の一括反映と未ロードの領域への保留へ渡す。通常の保存とマージは新形式だけを出力する。形式の版、対象となる旧構造、未対応の境界は実装と試験に合わせて仕様へ記録する。

## Identity描画の具体化
`CgeDepthMapping=Logarithmic|Identity` を数値型とは独立したゲームのビルド設定にする。既定はLogarithmic。Identityは通常の透視投影の深度をそのまま使い、対数距離・放射圧縮を適用しない。既存Stageシェーダーには正射影・影用の直接深度経路があるため、そのGPUパケットを再利用する。CPUの検証済みビューではIdentity透視と正射影を別の種類として扱い、間違った行列や復元用行列を受け付けない。

ゲームのカメラ提出を条件付きコンパイルで選び、非既定出力・生成ソースを分離する。数値ライブラリや物理キャッシュには描画設定を混ぜない。共通Renderingのビュー契約は明示的なIdentity作成APIを持ち、リサイズとデバイス復旧で同じ入力を再解決する。対数観測者の補助表示はIdentityゲームで提出しない。内部GIカメラと影は各パスが所有するビューを維持する。CPUの行列・深度・拒否条件を検証し、既存GPUのビュー・リサイズ・復旧試験へIdentityを統合する。

## 移行手順
1. 数値保存の共通境界と独立オラクル試験。
2. 設定別数値実装、依存先のビルド、静的な保存処理と旧形式読み込み。
3. 素材取り込みから配布までの接続。
4. 通し検証と重複試験・文書の整理。

## テスト計画
数値境界、設定間保存、破損、失敗時の不変、静的生成、設定伝達、描画、素材更新、実際の VS 操作、配布物を Debug/Release で確認する。CPU/GPU/UI の証拠を分ける。

## リスクと対策
型を公開する DLL は設定別に整合してビルドする。キャッシュを設定別に分離する。異なる数値設定間でシミュレーションのビット一致は要求しない。旧データと新形式を混同しない。

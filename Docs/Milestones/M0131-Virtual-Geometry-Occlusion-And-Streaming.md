# M0131 — 仮想ジオメトリの遮蔽判定と読み込み
- 日付: 2026-11-17
- 状態: Implementing
- 段階: ADR-0098 の段階 D の前倒し(ユーザーの判断。`Docs/目標、ロードマップ、戦略.md` は変えない)
- 決定: [ADR-0100](../Decisions/ADR-0100-Virtualized-Rendering.md) 決定 1・3
- 前の段階: [M0130](M0130-Virtual-Geometry-Build-And-Draw.md)(塊の階層のビルド、GPU の選択と間接描画、法線マップと三角形の下限)
- 機能 ID: F-L4-025(仮想ジオメトリの遮蔽判定と読み込み)。単位ごとに台帳へ登録する。

## 用語
| 語 | 意味 |
|---|---|
| 遮蔽判定 | 手前の物に隠れた塊を描かずに済ませること |
| Hi-Z | 距離の画像を、2×2 画素ごとに「いちばん遠い値」を取って半分ずつ縮めた画像の重なり(ミップ)。粗い段の 1 画素で、広い範囲の「これより遠い物は隠れている」が分かる |
| 2 パスの遮蔽 | 前のフレームで見えた塊を先に描き、その距離から Hi-Z を作って、残りの塊が隠れているかを調べてから描く方法。前のフレームの結果だけで捨てると、急に見えた物が 1 フレーム消えるため |
| ページ | 読み込みと追い出しの単位。ここでは「1 つのまとまりが作った塊の組」(葉の段では塊 1 つ) |
| 常駐 | ページが GPU に置かれていて、描ける状態 |
| 準備済み(ready) | あるまとまりを細かくしてよい状態。そのまとまりの入力(1 段細かい塊)のページがすべて常駐し、上のまとまりもすべて準備済みであること |
| 要求 | 選択の計算シェーダーが「このページがあればもっと細かく描ける」と書き出す印。描画器が読み戻して読み込みを始める |
| 予算 | 仮想ジオメトリのページに使ってよい GPU のメモリの上限 |

## 目的
仮想ジオメトリの描く量と持つ量を、見えている分と要る分だけに減らす。
- 隠れた塊を主パスで描かない(2 パスの遮蔽)。
- 塊のページを、画面で要る分だけ GPU に置く。足りないうちは、準備済みの粗い塊で描く。予算を超えたら理由を報告して粗いまま描く。

## 決めたこと
- **遮蔽判定は主パスだけに掛ける**: 塊の選択(細かさ)は、影・Lumen・カメラプレビューと共有している(M0130 単位 5)。カメラから隠れた物も影を落とし、Lumen の光を返すので、選択そのものからは外さない。細かさで選んだ一覧から、主パスで描く一覧だけを遮蔽で絞る。
- **Hi-Z は距離の画像から作る**(ADR-0100 決定 3): 主パスが書く物理距離(カメラからの距離、メートル)の最大を取って縮める。何も描かれていない画素(空、値 0)は無限に遠いとする。対数の深度の符号化に依存しないので、標準と放射状の深度のどちらでも同じ判定になる。
- **判定は球で**: 塊の包む球(成果物に既にある)のいちばん近い点の距離が、球が画面で覆う範囲の Hi-Z の最大より遠ければ隠れている。球がカメラに近すぎて画面の範囲を出せないときは、隠れていないとする(描きすぎる側に倒す)。
- **2 パスの流れ**(Omni と同じ): 1 パス目は前のフレームで見えた塊を、判定なしで描く。そこまでの距離で Hi-Z を作る。2 パス目は、細かさで選んだ残りの塊を Hi-Z で調べて、隠れていない塊だけを描く。最後に、細かさで選んだすべての塊を同じ Hi-Z で調べ、次のフレームの「見えた印」を書く。
- **遮蔽判定を切った絵と同じ絵**: 2 パス目は 1 パス目に描いた物の後ろにある物だけを捨てる。捨てた塊は描いても手前の物に負けるので、画素は変わらない。これを試験の約束にする。
- **ページは「まとまりが作った塊の組」**: 根のまとまりのページは常に置く。細かくするには、そのまとまりの入力のページが全部要る。準備済みの印は CPU が常駐の変化から上から順に求めて GPU へ送る(Omni の方式)。準備済みの印は、親が準備済みでなければ子も準備済みにしない。こうすると、細かさの判定に「準備済みでなければ十分とみなす」を足しても、親から子へ十分さが受け継がれ、割れ目も重なりも出ない。
- **置き場は共通部品を使う**: ページの置き場の割り当ては `PageSlotAllocator`、報告は `StreamingReport`、送りはアップロードの輪、要求の読み戻しは読み戻しの輪(M0129 単位 5・6)。

## 単位
| 単位 | 内容 | 合格の条件 | 状態 |
|---|---|---|---|
| 0 | この文書 | 参照が正しい | 済 |
| 1 | 距離の画像から Hi-Z を作る計算シェーダー | CPU で求めた Hi-Z と全段で一致、空は無限に遠い、奇数の大きさの縁も覆う、デバッグ層のエラー 0 | 済 |
| 2 | 主パスの 2 パスの遮蔽 | 遮蔽を切った絵と画素が同じ、壁の後ろの塊が描かれない、カメラを回しても穴が出ない、影と Lumen は変わらない | |
| 3 | ページの置き場(塊ごとに頂点と索引を持つ形) | 全部を置いた状態で M0130 の絵と同じ | |
| 4 | 常駐・準備済み・要求と、読み込みの制御 | 根だけから始めて数フレームで全部置いた絵に追いつく、読み込み中に穴や重なりが出ない、予算を超えたら理由を報告して粗く描く | |
| 5 | 計測と締め | 描いた三角形、GPU の時間、常駐の量 | |

## 試験で固定する約束
- 遮蔽判定は見える物を消さない(遮蔽を切った絵と同じ)。
- 影・Lumen・カメラプレビューの絵は、遮蔽判定を入れても変わらない。
- 読み込みのどの途中でも、描いた塊は割れ目なく 1 回ずつ面を覆う。
- 置き場の数と予算を超えない。根のページは追い出さない。

## 範囲外
影の視点での遮蔽判定と、光から見た細かさ(M0132)。地形のマス(M0134)。ファイルの一部だけを読む読み込みは単位 4 の結果を見て決める(まず、取り込んだ成果物を CPU に持ったまま GPU の置き場を出し入れする)。

## 実行記録: 単位 1 Hi-Z(2026-11-17)
- **作ったもの**: 計算シェーダー `assets/Shaders/HiZ.hlsl`(1 回で 1 段)、段の決まりと CPU の答え `src/Engine/Rendering/Streaming/HiZPyramid.cs`、D3D12 の実行 `src/Windows/Graphics/StageHiZ.cs`(段ごとの SRV と UAV、段ごとの状態の切り替え)。描画器は試験の印 `BuildHiZAfterMainPassForTesting` があるときだけ主パスの最後に作る(`StageRenderer.Occlusion.cs`。単位 2 で主パスの途中へ移す)。テクスチャの読み戻し `GpuTextureReadback.Read` は段(サブリソース)を選べるようにした。
- **段の大きさ**: 初めは「半分の切り上げ」で作ったが、D3D12 のミップは「半分の切り捨て」なので段 1 から大きさがずれ、GPU の値が CPU と合わなかった(317×181 の画面で段 1 が 80×46 のつもりが 79×45)。Omni と同じく、段 0 を「画面の半分(切り上げ)を縦横それぞれ 2 のべき乗へ切り上げた大きさ」にして、どの段もちょうど半分にした。画面の外にはみ出した画素は 0 とし、いちばん遠い値には効かない。
- **試験**: エンジンのテスト `HiZPyramidTests`(段の大きさ、空は無限に遠い、奇数の大きさでどの画素も最後の段に届く、段 0 の各画素が元の 2×2 のいちばん遠い値)。Windowsのテスト `HiZGpuTests.Warp_EveryLevelMatchesTheCpuPyramid`(317×181 の WARP で床・箱・空を描き、GPU の全 9 段が CPU と 1 画素ずつ同じ、デバッグ層のエラー 0)。固定 7 画像、仮想ジオメトリ、AO の GPU の試験も合格(Hi-Z は印が無いと作らないので、既存の絵は変わらない)。

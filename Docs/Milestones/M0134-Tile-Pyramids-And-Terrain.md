# M0134 — タイルの前処理と地形
- 日付: 2026-11-18
- 状態: Done
- 段階: ADR-0098 の段階 D の前倒し(ユーザーの判断。`Docs/目標、ロードマップ、戦略.md` は変えない)
- 決定: [ADR-0100](../Decisions/ADR-0100-Virtualized-Rendering.md) 決定 7
- 前の段階: [M0133](M0133-Virtual-Object.md)(VirtualObject)
- 機能 ID: F-L7-060(大きな画像のタイルの前処理)、F-L5-051(地形)

## 用語
| 語 | 意味 |
|---|---|
| タイルの階層 | 大きな画像を 256×256 などの小さな画像(タイル)に分け、さらに半分・4 分の 1 … の粗い段も作ったもの。必要な所の必要な細かさだけを読める |
| 索引とまとめファイル | タイルの階層の置き場。索引(`*.cgetiles`)にタイルの場所を、まとめファイル(`*.cgetilepack`)にタイルの中身を続けて入れる。1 タイル 1 ファイルにしない(数百万件になるため) |
| 正距円筒 | 経度と緯度を等間隔に並べた地図の形。惑星の全球の画像はこの形が多い |
| マス | 地形を四分木で分けた 1 区画。近くは細かく、遠くは粗く分ける |
| 割れ目 | 細かいマスと粗いマスの境で、頂点がずれてすき間が見えること |

## 目的
- NASA などの大きな素材(TIFF と PDS の IMG)を、メモリに全部載せずに少しずつ読み、タイルの階層にする。
- 平面と球の地形を、カメラから見た細かさでマスに分けて描く。隣のマスとの間が割れず、選び方は決定的。
- 月の実データ(LOLA の標高、23040×11520)で確かめる。

## 決めたこと
- **高さは点だけで決まる**: マスの深さで高さの細かさを変えると、隣のマスと共有する頂点の高さが食い違って割れる。高さは格子の点(球は向き、平面は位置)だけで決め、タイルの段は地形ごとに 1 つ選ぶ(`Terrain.HeightLevel`)。遠くのマスは細かい高さを点で拾うので、マスが切り替わるときに形が少し変わる(限界)。
- **マスは普通のメッシュとして描く**: ADR-0100 決定 7 は「マスの格子を VG の形として同じ描画経路へ流す」としていたが、マスの選択がすでに細かさを決めているので、仮想ジオメトリの塊の階層は作らず、GPU シーンの普通のメッシュと物(枠)を使い回す。描画の経路は M0129 の GPU シーンで同じ。
- **64 ビットの浮動小数の画素は読まない**: エンジンは画素の値を float で持つ(NUM001)。読む時点で拒む。
- **置き場所**: マスの計算は Q64.64(`Numerics`)が要るので `src/Numerics/World/Terrain` に置く(エンジン本体の L4 は `Numerics` を参照しない)。

## 検証の結果
- **読み手とタイルの階層**(エンジンのテスト `TilePyramidTests` 15 件): PDS のラベル付き・ラベル無しの IMG、TIFF の 8 通り(圧縮なし・LZW・Deflate、帯とタイル、予測あり、チャンネルを画素ごと・面ごと、8/16/32 ビット)を同じ値で読み、読めない形(JPEG の圧縮、TIFF でないもの)ははっきり拒む。タイルの階層は段 0 が元の値と一致し、段 L+1 は段 L の 2×2 の平均、値の無い所を混ぜず、同じ入力から同じバイト列。
- **マス**(エンジンのテスト `TerrainCellsTests` 4 件): 平面と、月の大きさの球(面の角の近く、上 30 km)で、マスは面をすき間なく覆い、隣との深さの差は 1 まで、共有する格子の点は Q64.64 で完全に同じ位置(面をまたいでも)。粗い隣に接するマスがある場面で確かめた。
- **実行時**(Windowsのテスト `TerrainTests`、WARP): 平らな地形で 10 を超えるマスを描き、止まったカメラでは作り直さず、動くと空いた枠を使い回す。起伏のタイルで絵が変わる。1 フレームに 50 マスまでにすると、作れていないマスがフレームごとに減って 0 になる(同じマスを作り直さない)。
- **月の実データ**: LDEM_64 を `Cge content compile-tiles`(`--raw 23040x11520:int16:le --scale 0.5 --bounds 0,360,90,-90`)で 59 秒でタイルの階層にした(8 段、5,460 タイル、まとめファイル 723 MB。元の int16 を float で持つので元より大きい)。ところどころ元の値と一致。軌道から 96 マス、30 km から 1,776 マスで描いた(`.artifacts/m0135/`)。

## 範囲外
- 色のタイルを地形に貼ること(M0135 の RVT)。
- マスの深さに合わせて高さの段を変えること(割れない形で行うには、粗い隣と共有する頂点の高さの決め方が要る)。
- 地形の当たり判定。
- 地形だけのレベル(描画器が物 1 つ以上を要る)。見本 `UserEcsProject/Scenes/TerrainSampleScene.json` は小さな箱を 1 つ持つ。

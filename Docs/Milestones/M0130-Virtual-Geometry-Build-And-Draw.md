# M0130 — 仮想ジオメトリのビルドと描画
- 日付: 2026-11-17
- 状態: Implementing
- 段階: ADR-0098 の段階 D の前倒し(ユーザーの判断。`Docs/目標、ロードマップ、戦略.md` は変えない)
- 決定: [ADR-0100](../Decisions/ADR-0100-Virtualized-Rendering.md) 決定 3・4・8
- 前の段階: [M0129](M0129-Gpu-Scene-Foundation.md)(GPU シーン、番号引き、アップロードと読み戻しの輪、画面上の大きさの式)
- 機能 ID: F-L7-059(仮想ジオメトリのビルド)、F-L4-024(仮想ジオメトリの描画)。単位ごとに台帳へ登録する。

## 用語
| 語 | 意味 |
|---|---|
| 仮想ジオメトリ(VG) | メッシュを小さな塊に分け、粗い版から細かい版までの階層を作っておき、画面で要る細かさの塊だけを描く仕組み |
| 塊(クラスタ) | 128 枚以下の三角形のまとまり。描く単位 |
| まとまり(グループ) | 隣り合う 8 個以下の塊を合わせたもの。まとめて半分に減らし、1 段粗い塊を作る単位 |
| 外周の固定 | まとまりの外周(隣のまとまりと共有する縁)の頂点を動かさないこと。粗さの違う塊が隣り合っても割れ目が出ない |
| 誤差 | 粗い塊が、元の形からどれだけずれうるか(メートル)。画面上の大きさの式で画素に直して、細かくするかを決める |
| 階層(DAG) | 粗い塊が、どの細かい塊のまとまりから作られたかの関係。1 つの塊が上の段の 2 つのまとまりに関わることがあるので木ではない |
| QEM(誤差の二次形式) | 各頂点に「周りの面からの距離の二乗」の式を持たせ、辺を縮めたときの誤差を見積もる簡略化の方法 |
| 代理メッシュ | 粗い段の形。Lumen のカード、DDGI、距離場、ピッキングなど、細かさの要らない処理に渡す |

## 目的
細かいメッシュを、塊の階層に前処理し(ビルド)、画面上の大きさに合った細かさの塊だけを GPU が選んで描く。M0129 の GPU シーン・間接描画・番号引きの上に作る。従来のメッシュと同じ材質・照明・影の経路を通す。

## 決めたこと
- **簡略化は自前の C#**: Omni は C の部品(meshoptimizer)を使ったが、エンジンが持つ実装を正しさの基準にする決まりに合わせ、QEM による辺の縮約を C# で書く。位置の誤差は絶対値(メートル)で返す。法線と UV も誤差に重みを付けて入れる(Omni と同じ重み: 法線 0.5、UV 0.1)。
- **数値は Omni に合わせる**: 塊は 128 三角形以下、まとまりは 8 塊以下、1 段で目標 50%、親の誤差は子の 1.25 倍以上、1 段の削減が 92% を超えたら打ち切って残りを 1 つの根にする。
- **外周の判定は位置で**: 法線や UV の継ぎ目で同じ位置の頂点が分かれても、位置で見て 2 枚の三角形が共有する辺は内側とする(Omni と同じ。継ぎ目まで固定すると角ばったメッシュが減らない)。
- **材質は 1 つ**: このエンジンのメッシュは 1 材質なので、材質の境の固定は要らない(Omni の材質の継ぎ目の処理は持たない)。
- **選択は「独立判定とヒステリシス」だけ**: 塊ごとに「自分の誤差の画素数がしきい値以下」かつ「親のまとまりの誤差の画素数がしきい値より大きい」なら描く。親の誤差が子の 1.25 倍以上なので、ヒステリシス 0.1 でも穴や重なりが出ない(Omni の導いた条件)。
- **計算シェーダーの共有コード**: `ScreenSizeMetric.Hlsl` の文字列を、VG の計算シェーダーの組み立て時に先頭へ付ける(単位 4 で仕組みを決める)。
- **両面**: 元のメッシュと同じ見た目を優先し、既定は元のメッシュの設定どおり。

## 単位
| 単位 | 内容 | 合格の条件 | 状態 |
|---|---|---|---|
| 0 | この文書 | 参照が正しい | 済 |
| 1 | QEM の簡略化(C#) | 固定した頂点は動かない、誤差の上限を守る、目標の数まで減る、裏返りを作らない、同じ入力で同じ結果 | 済 |
| 2 | 塊の階層のビルド | 割れ目が出ない(どの選び方でも、選んだ塊の縁が元の縁と一致する)、誤差が親で増える、包む球が親で子を包む、同じ入力で同じバイト列 | 済 |
| 3 | 成果物の形と取り込みの設定、代理メッシュ | 書いて読んで同じ、壊れた入力を断る、取り込みで作られる | 済 |
| 4 | GPU で塊を選んで間接描画(主パス) | 原本メッシュとの画像の差が小さい、デバッグ層のエラー 0 | 未 |
| 5 | 影・AO・Lumen の前処理を同じ選択で描く。代理メッシュを渡す | 影が落ちる、既存の試験が通る | 未 |
| 6 | 三角形の下限と法線マップ(計測して採否を決める) | 3 通りの比較の数値 | 未 |

## 試験で固定する約束
- 割れ目が出ない: どんなしきい値で選んでも、選んだ塊の三角形の集まりの「1 枚だけが使う辺」が、元のメッシュの開いた縁と一致する。
- 誤差は親で子の 1.25 倍以上。包む球は親が子を包む。
- 同じ入力から同じバイト列。
- 固定した頂点は簡略化で動かない。

## 範囲外
遮蔽判定と読み込み(M0131)、スキニング、半透明、仮想シャドウ(M0132)。

## 実行記録: 単位 1 QEM の簡略化(2026-11-17)
- **作ったもの**: `src/Cooking/VirtualGeometry/QuadricSimplifier.cs`。辺の片側を残す縮約(頂点を隣の頂点の位置へ寄せて消す)。新しい位置を作らないので、固定した頂点は動かず、残る頂点の法線・UV は元の値のまま。
  - 継ぎ目(同じ位置に法線や UV の違う頂点がある所): 消える側の各頂点の移し先を、両方の位置を含む三角形の中の頂点に決める。移し先が 1 つに決まらない縮約は行わない。
  - 誤差: 寄せた先での、元の面までの距離の二乗の和の平方根。開いた縁には、縁を含み面に垂直な面(重み 10)を足す。
  - 行わない縮約: 固定した位置を消す、面の向きが内積 0.2 未満に変わる、リンク条件を破る(形のつながりを壊す)、誤差の上限を超える。
  - 同じ費用なら位置の番号の小さいほうから。費用が周りの縮約で増えていたら積み直す。
- **数値の決まり**: 初めは `double` で書いたが、エンジンの数値の決まり(NUM001。`double` は外部との境界だけ)で組み立てが止まった。`float` で書き直した。
- **試験**: `tests/焼き込みのテスト/VirtualGeometry/QuadricSimplifierTests.cs` の 5 件が合格。縁を固定した平らな格子(512 枚)は誤差 0 で 1/4 未満に減り、縁の頂点はすべて残り、裏返りが無い。球は目標まで減り、誤差の上限を 1/4 にすると、その上限を守って早く止まる。面ごとに法線の違う(角が継ぎ目の)細かく分けた箱(432 枚)は、誤差 0 のまま 12 枚まで減り、どの三角形の頂点の法線もその面の向き。同じ入力で同じ結果。壊れた入力は断る。
- **途中で外れた見込み**: 箱が 28 枚で止まったとき、`-0` と `0` が別の位置になっているためと考えて、位置をそろえる処理を足したが、結果は変わらなかった(そろえる処理は害が無いので残した)。原因は試験の箱の作り方で、隣り合う面で辺の上の点を違う順で計算していたため、最後の桁が 1 つずれて同じ位置にならなかった。座標を `(2I−N)/N` で正と負が対称になるように計算すると 12 枚になった。
- **分かったこと**: 継ぎ目は位置がぴったり同じときだけつながる。Omni はビルドの初めに位置をメッシュ全体の格子にそろえる(量子化)。単位 2 でこれを取り入れる。

## 実行記録: 単位 2 塊の階層のビルド(2026-11-17)
- **作ったもの**: `src/Cooking/VirtualGeometry/VirtualGeometryBuilder.cs`(ビルド)と、出力の形 `src/Engine/Content/VirtualGeometry/VirtualGeometryData.cs`(頂点、塊、まとまり、メッシュ)。単位 3 で成果物として書き出すので、出力の形は L6 に置いた。
  - 手順は Omni と同じ: 位置を 16 ビットの格子にそろえる → 三角形を重心の最も広い軸の中央値で二分割して 128 枚以下の塊にする → 段ごとに同じ位置を多く共有する塊を 8 個以下のまとまりにし、外周(まとまりの中で 2 枚以外の三角形が使う辺)を固定して半分に減らす → 親の誤差は「子 + 簡略化の誤差」と「子 × 1.25」の大きいほう、親の球は子の球を包む → 1 段で 92% より減らなければ残りを 1 つの根にする。
  - 塊の選び方の情報: 塊ごとに、自分を作ったまとまりと、自分を使って次の段を作ったまとまり(根なら無し)を持つ。
  - Omni との違い: 材質は 1 つなので材質の境の固定は持たない。小さな部品を取り除く処理(Omni の pruning)はまだ入れていない(小さな部品の多いメッシュは早く打ち切られる)。
- **試験**: `tests/焼き込みのテスト/VirtualGeometry/VirtualGeometryBuilderTests.cs` の 7 件が合格(単位 1 と合わせて 12 件)。
  - 球(9,216 枚)が 4 段以上になり、塊はすべて 128 枚以下、元の三角形はいちばん細かい段にすべて残り、根は元の 1/8 未満。親の誤差は子の 1.25 倍以上、親の球は子の球を包む。
  - 割れ目が出ない: 誤差のしきい値をどの段の誤差に選んでも、選んだ塊の三角形で、どの辺もちょうど 2 枚の三角形が使う(球と、角が継ぎ目の箱)。カメラ 4 か所 × 画素のしきい値 4 通りで、画面上の大きさの式(`ScreenSizeMetric`)で選んでも同じ。
  - 同じ入力で同じ結果。1 つの塊に収まるメッシュは、それ自身が根。壊れた入力は断る。
- **途中で見つけたこと**: 初めは球で、いちばん細かい段を選んでも 8 本の辺が閉じていなかった。試験の球の作り方で、経度の継ぎ目と極の点が三角関数の丸めで最後の桁だけずれていた(`sin(π)` は 0 にならない)。位置を格子にそろえても、値がちょうど格子の境目にかかると別の格子点に丸まり、つながらない。継ぎ目と極にまったく同じ値を使うように試験の球を直すと、すべて閉じた。実際の書き出し(glTF など)では継ぎ目の頂点は同じ値を写すのが普通だが、入力の開いた辺を数えて知らせる仕組みは、単位 3 の取り込みで足す候補。

## 実行記録: 単位 3 成果物の形と取り込みの設定(2026-11-17)
- **置き場の判断**: 新しい成果物の種類を足さず、モデルの追加データ(`ModelRuntimeBlock`、種類 `cge.virtual-geometry/1`)に、メッシュ番号とサブメッシュ番号ごとの塊の階層を持たせた。成果物の形の取り決めを変えずに足せる。大きさの上限はモデルの成果物と同じ 512 MB(分けて読み込むのは M0131)。
- **読み書き**: `src/Engine/Content/VirtualGeometry/VirtualGeometryCodec.cs`。リトルエンディアンの固定長の並び。書くとき -0 を 0 にし、NaN と無限大を断る。読むとき、番号の範囲、塊の三角形の数(1〜128)、塊が自分を作ったまとまりの中にあること、親が無い塊は根のまとまりのものであること、余りのバイト、順番を確かめる。同じ入力から同じバイト列。
- **取り込みの設定**: エンジン共通の設定に `virtualGeometry.enabled`(`false`/`true`、既定 `false`)を足した(`src/Cooking/ImportOptions.cs`)。どの取り込みでも `.meta` に書ける。`true` なら、成果物を作るとき(`ModelArtifactPreparation.Prepare`)に、骨とモーフの無いメッシュのサブメッシュごとに、使う頂点だけに詰めてからビルドする。
- **代理メッシュ**: `VirtualGeometryMesh.ProxyIndices()` が根の段の塊の三角形を返す(使うのは単位 5)。
- **試験**: 焼き込みのテストの `VirtualGeometryCodecTests` 3 件(書いて読んで同じでバイト列も同じ、切れた・余った・合言葉の違う・番号の外・NaN・重なる項目・根の外を断る、代理メッシュは根の段で元より粗い)。エンジンのテストの `ModelArtifactPreparationTests.VirtualGeometryIsBuiltOnlyWhenTheImportOptionAsksForIt`(設定が `true` なら、実行時の読み込みから追加データが読め、`false` なら無い)。単位 1〜2 と合わせて焼き込みのテスト 15 件、エンジンのテスト 24 件(層の検査を含む)が合格。
- **途中で直した誤り**: 読む側で、残りのバイト数の見積もりに塊とまとまりを 36 バイトと書いていた(実際は 32 バイト)。往復の試験が「途中で切れている」で失敗して分かった。
- **影響**: エンジン共通の設定を足したので、設定から作る値(`OptionsHash`)が変わり、すべてのモデルが次の組み立てで一度作り直される。設定が `false` なら成果物の中身は変わらない。

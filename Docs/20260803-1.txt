# C#GameEngine エディター操作設計

## 目的

C#GameEngine のエディター操作では、次の要件を同時に満たすことを目標とする。

- Unity 利用者が違和感なく操作できる
- Unreal Engine 利用者も慣れた操作を選べる
- オブジェクト配置と視点操作が競合しない
- コライダー、ポリゴン、グリッドを使った複数のスナップ方式を提供する
- すべての操作をユーザーが自由に変更できる
- 入力割り当てを変更しても、内部の操作体系は一貫させる

マウスボタンそのものに機能を固定するのではなく、次の要素から実行する操作を決定する。

1. 操作開始位置
2. 現在の選択状態
3. 現在のツール
4. 修飾キー
5. 操作プロファイル

---

## 基本方針

操作を次の3層に分ける。

1. 選択・オブジェクト操作
2. 視点操作
3. スナップ方式

視点操作とオブジェクト操作を可能な限り別の入力へ分離し、同じ入力が同じコンテキストで複数の意味を持たないようにする。

---

## 推奨デフォルト操作

| 開始位置・状態 | 操作 | 動作 |
|---|---|---|
| 空間から左ドラッグ | LMB | 範囲選択 |
| 未選択オブジェクトを左クリック | LMB | 選択 |
| 選択済みオブジェクトを左ドラッグ | LMB | 通常移動 |
| 選択済みオブジェクトを Ctrl+左ドラッグ | Ctrl+LMB | コライダー同士が接する位置まで移動 |
| 選択済みオブジェクトを Shift+左ドラッグ | Shift+LMB | ポリゴン同士が極力交差しない位置まで移動 |
| 選択済みオブジェクトを Ctrl+Shift+左ドラッグ | Ctrl+Shift+LMB | 表示中の XYZ 平面グリッドへスナップ |
| 中ドラッグ | MMB | 視点平行移動 |
| 右ドラッグ | RMB | 視点回転 |
| Space+左ドラッグ | Space+LMB | UE 型の前後移動＋左右旋回 |
| ホイール | Wheel | 視点前後移動 |

通常時は編集操作を優先し、Space を押している間だけ UE 型ナビゲーションへ切り替える。

---

## 左ドラッグの操作判定

左ドラッグには、範囲選択、オブジェクト移動、カメラ操作など複数の用途がある。

操作開始位置によって動作を決定する。

```text
左ボタンを押した位置
├─ ギズモ上
│  └─ ギズモ操作
├─ 選択済みオブジェクト上
│  └─ オブジェクト移動
├─ 未選択オブジェクト上
│  └─ 選択
└─ 空間上
   ├─ Spaceあり
   │  └─ UE型カメラ移動
   └─ Spaceなし
      └─ 範囲選択
```

ドラッグ開始後は、ボタンを離すまで操作を変更しない。

例えば、オブジェクト上からドラッグを開始した後にカーソルが空間へ移動しても、途中から範囲選択やカメラ操作へ切り替えない。

---

# スナップ方式

## Ctrl：Collider Contact Snap

Ctrl+左ドラッグでは、移動元オブジェクトと対象オブジェクトのコライダー同士が接する位置まで移動する。

```text
移動元オブジェクトのコライダー
        ↓
移動方向へ Sweep
        ↓
最初に衝突する位置で停止
```

接触対象は次の組み合わせとする。

```text
自身のコライダー ↔ 対象のコライダー
```

ピボットと対象コライダーを接触させる方式にはしない。

ピボットは Transform 計算やドラッグ操作の基準として使用し、接触判定そのものには使用しない。ピボット位置はモデルごとに異なるため、接触対象にすると配置結果が不自然になりやすい。

### オプション

- 接触後に面に沿ってスライドする
- 最初に接触した位置で完全停止する
- Contact Offset を指定する
- Trigger を対象外にする
- 選択中のオブジェクト同士を無視する
- 子コライダーを個別に扱う
- 複数選択をひとつの剛体形状として扱う

---

## Shift：Mesh Surface Fit

Shift+左ドラッグでは、物理コライダーではなく、表示ポリゴンを基準にオブジェクト同士を近づける。

```text
自身のポリゴン
    ↕
対象ポリゴン
```

### 基本動作

- 表面同士を可能な限り近づける
- 明確な内部交差が起きる直前で停止する
- 薄い形状や複雑な凹形状では多少の重なりを許容する
- コライダーが見た目と異なるオブジェクトの配置に使用する
- 完全な物理衝突判定ではなく、視覚的に自然な配置を優先する

名称候補は次のとおり。

- Surface Fit
- Visual Contact
- Mesh Contact Snap

内部実装では、Mesh BVH を使った候補三角形検索と、移動方向に対する保守的な接触判定を使用する。

### 精度設定

- Fast
- Balanced
- Precise

Fast では Bounds や簡略化 Mesh を利用し、Precise では実ポリゴン同士の判定を増やす。

---

## Ctrl+Shift：Grid Plane Snap

Ctrl+Shift+左ドラッグでは、操作平面を表示し、選択オブジェクトをグリッドへスナップする。

```text
XY
XZ
YZ
```

使用する平面は、次の優先順位で決定する。

1. 現在操作中のギズモ平面
2. 最後に使用した平面
3. カメラに最も正対している平面
4. X、Y、Z キーによる明示指定

### グリッド表示

- ドラッグ開始時に対象平面を表示
- 選択中の平面を強調
- スナップ間隔を画面上に表示
- ローカル座標とワールド座標を切り替え可能
- 階層グリッドに対応

### スナップ基準

- Pivot
- Center
- Bounds Min
- Bounds Max
- 選択頂点
- 接触点

デフォルトは Pivot とし、必要に応じて Bounds や頂点へ変更できるようにする。

---

# 視点操作

## 中ボタン：視点平行移動

MMB は原則として視点平行移動専用にする。

```text
MMB = 常に視点平行移動
```

オブジェクト上で中ドラッグした場合だけ別の動作にすると、画面全体をオブジェクトが覆っている状況で視点移動できなくなる。

そのため、中ドラッグによるオブジェクト操作は標準設定には含めず、カスタム割り当てとしてのみ許可する。

---

## 右ボタン：視点回転

RMB は視点回転専用にする。

```text
上下ドラッグ：視点を上下に見回す
左右ドラッグ：視点を左右に見回す
```

RMB を押している間は、一時的にマウスカーソルをロックできるようにする。

### オプション

- Y 軸反転
- 感度
- 加速度
- 慣性
- カーソルロック
- 水平回転のみ
- 選択対象を中心に回転

---

## Space+左ドラッグ：UE 型ナビゲーション

Space を押している間だけ、LMB を UE 型ナビゲーションへ切り替える。

```text
上下ドラッグ：視点を前後に移動
左右ドラッグ：視点を左右に見回す
```

これにより、通常の LMB 編集操作と UE 型カメラ操作を両立できる。

Space は一時ナビゲーションモードとして扱う。

```text
通常状態
└─ LMB = 選択・移動・範囲選択

Space保持中
└─ LMB = UE型カメラ操作
```

---

# 平行移動方向の違い

Unity 型と UE 型では、中ドラッグの方向に対する考え方が異なる。

## Unity 型：シーンをつかむ

```text
左へドラッグ
→ 画面上のシーンが左へ動く
→ カメラ自体は右へ移動
```

## UE 型：カメラを動かす

```text
左へドラッグ
→ カメラが左へ移動
→ 画面上のシーンは右へ動く
```

両方を設定として提供する。

```csharp
public enum PanBehavior
{
    GrabScene,
    MoveCamera
}
```

さらに、軸ごとの反転設定を持たせる。

```text
Invert Pan X
Invert Pan Y
Invert Look X
Invert Look Y
Invert Dolly Y
```

```text
    → UnrealStyleNavigate
```

# 操作状態の固定

入力開始時に、そのドラッグで実行する操作を確定する。

```csharp
public enum ActiveInteraction
{
    None,
    Selecting,
    MarqueeSelecting,
    MovingObject,
    ColliderSnapping,
    MeshSnapping,
    GridSnapping,
    PanningView,
    LookingView,
    UnrealNavigating
}
```

ドラッグ中にカーソル位置や修飾キーが変化しても、原則として ActiveInteraction は変更しない。

ただし、スナップ方式については設定により、ドラッグ中の修飾キー切り替えを許可してもよい。

### 固定モード

```text
ドラッグ開始時の修飾キーで方式を固定する
```

### ライブ切り替えモード

```text
ドラッグ中に Ctrl / Shift を押すとスナップ方式を変更する
```

標準設定は固定モードとする。ライブ切り替えは上級者向け設定にする。

```text
LMB             選択・範囲選択・通常移動
```

編集操作は左、平行移動は中、見回しは右、特殊スナップは修飾キー、UE 型移動は Space による一時ナビゲーションという体系になる。

---

## Unity Compatible

Unity 利用者向けのプロファイル。

```text
LMB                選択・ギズモ操作

Alt+RMB            ズーム

RMB                フライスルーまたは見回し
Ctrl+Shift+LMB     グリッドスナップ
```

Unity と完全に一致させるのではなく、C#GameEngine 固有の接触スナップ機能を追加する。

---

## Unreal Compatible

UE 利用者向けのプロファイル。

```text
LMBドラッグ        前後移動＋左右旋回
MMBドラッグ        視点平行移動
RMBドラッグ        視点回転

```

このプロファイルでは、通常の LMB ナビゲーションと範囲選択が競合するため、選択ツールとナビゲーションツールを明示的に分離する。

# 入力競合の検出

同じコンテキストで同じ入力に複数の操作が割り当てられている場合は、警告する。

```text
警告:
「Pan View」と「Collider Contact Move」が
SelectedObject コンテキストの MMB に割り当てられています。
```

競合には次の種類がある。

- 完全競合
- コンテキスト競合
- 修飾キー包含競合
- ドラッグとクリックの競合
- 一時モードとの競合

### 競合解決方法

1. より具体的なコンテキストを優先する
2. 修飾キーが多い割り当てを優先する
3. ギズモ操作を優先する
4. 一時ナビゲーションモードを優先する
5. 解決できない場合はユーザーへ警告する

---

# 入力評価の優先順位

推奨優先順位は次のとおり。

```text
1. モーダルダイアログ
2. キャンセル操作
3. 一時ナビゲーションモード
4. ギズモ
5. 頂点・辺・面編集
6. 選択済みオブジェクト
7. 未選択オブジェクト
8. 空間
9. グローバルショートカット
```

入力の判定は、単純なキーコード比較ではなく、優先順位付きのルールとして評価する。

# 実装方針

すべての操作を同時に固定するのではなく、次の構造にする。

```text
すべての操作能力を実装する
        +
矛盾しない標準プロファイルを提供する
        +
ユーザーが自由に割り当てられる
```

内部では EditorAction を基準にし、Unity 型、UE 型、C#GameEngine 型の違いは InputBinding の差として扱う。

これにより、入力方式を変更しても、オブジェクト移動、スナップ、カメラ制御などの実装コードを共通化できる。

---

# 最終推奨仕様

C#GameEngine の標準操作は次のとおりとする。

```text
LMB             選択・範囲選択・通常移動
Ctrl+LMB        コライダー接触移動
Shift+LMB       ポリゴン表面接触移動
Ctrl+Shift+LMB  XYZグリッドスナップ

MMB             常に視点平行移動
RMB             常に視点回転
Space+LMB       UE型の前後移動＋左右旋回
Wheel           視点前後移動
```

この設計により、次の一貫性を得られる。

- 左ボタンは選択と編集
- 中ボタンは平行移動
- 右ボタンは見回し
- Ctrl は物理的な接触
- Shift は視覚的な表面接触
- Ctrl+Shift はグリッド
- Space は一時ナビゲーション

操作能力は固定せず、プロファイルとカスタム入力設定によって、Unity 型、UE 型、独自型をすべて許容する。

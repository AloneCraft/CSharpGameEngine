## Unreleased

- Added radial (logarithmic) depth, a native port of the Unity asset Omni (ADR-0076, M0099, F-L5-038/F-L5-039). A scene `Camera` with `DepthMapping: "Radial"` (the default since M0100, see below; `RadialTransitionMeters`, default 1 m) orders surfaces correctly from millimetres to the Q64.64 range in one depth buffer while rendering the standard image; any NearZ/FarZ may be used and the editor's runtime view follows the scene camera. A `RadialObserver` component adds an inset that shows the compressed world from outside with the camera marked. Standard cameras render bit for bit as before (pinned by `StandardModeGoldenFrameTests`). The Stage shader ABI gains five radial entries (14 in all) and the `FrameCB.DepthMapping0/1` packet (now `stage-v10`, see the per-object depth entry): a custom Stage graph copied from an earlier Stage graph must be re-copied. The radial main pass keeps early depth rejection through a conservative depth.
- Fixed the viewer framing models about 1.7 times too far away: it wrapped the mesh's bounding sphere in a cube and framed that cube's circumscribed sphere; it now frames the mesh's own bounds (a sphere fills about 11 % of the view instead of 3.5 %).
- Scene JSON values the runtime or the compiler would reject are now build errors at their JSON position (SCENE203): a physical light value outside its range (for example a negative colour), a number beyond float, a LogicalScalar beyond the Q64.64 range. Such a scene used to build and then throw when the game instantiated it.
- Fixed the Scene Designer's runtime view ending when an edited value is one the component's own type rejects (a position beyond the Q64.64 range, a negative light colour): such a value now counts as a mismatch, and the view keeps the last good value.
- Fixed the C# scene to JSON converter throwing for a `float.NaN` or infinity constant and writing an unreadable document for a `double` one: such a value is now reported like any other value JSON cannot hold.
- Fixed scene JSON rejecting every value of a `ulong` member, although the C# scene converter and the Inspector write them; the schema now lists `ulong` members as integers.
- Fixed a scene JSON number beyond the range of its `double` or `decimal` member generating code that did not compile: it is now a SCENE203 error at the number, as a number beyond `float` already was.
- Fixed the Inspector accepting `NaN` and `Infinity` in a float field and writing them into the scene as `NaNf` / `Infinityf`, which do not compile: the field now takes finite numbers only.
- Fixed scene JSON documents whose components have members, constructor parameters or enum members named like C# keywords (a field declared `@class`) generating code that did not compile: the generated scene now writes those names with the verbatim prefix.
- Fixed the project template wizard keeping a rebuilt SDK package out of its local feed when the old one had the same length: it now compares the bytes. The README also explains that NuGet keeps using the first extraction of a version.
- Fixed the Preview Host and the resident bridges failing to stop while a client had sent only part of a request (audit AUD-003): they read each request with their lifetime and a 30-second receive deadline, and the Preview Host drops such a client so its single pipe serves the next one.
- Fixed a manifest update cancelled while its last artifact was being read still switching to the new manifest and reporting success (audit AUD-002): the commit now observes the cancellation and keeps the last-known-good manifest.
- Fixed snapshots of cells holding typed lights failing to restore, even right after their capture (audit AUD-001): the snapshot codec now writes a validated value type (the light quantities) as its constructor's properties and reads it back through that constructor, which also rejects an out-of-range value. Archetypes holding lights get a new schema fingerprint (such snapshots never restored before).
- The hermetic clean build (`verification.clean-build`) now builds its empty owned root with a plain build instead of a Rebuild: a Rebuild can clean the shader compiler, scene schema writer or Feature Runner after a project built it for its own use, because that nested build shares the solution's project instance (audit AUD-004; developer Rebuilds remain exposed, see the audit addendum).
- Fixed parallel FBX imports crashing the process with an access violation: `FbxImporter` attached and detached AssimpNet's process-wide log stream around each import, and only the resident bridge serialized it. The importer now serializes that part itself (which also keeps each import's diagnostics its own).
- Fixed a radial scene camera with a non-positive `RadialTransitionMeters` (typed on the way to 0.5, say) being able to stop the whole Scene view: the preview protocol rejects a frame with one invalid camera, so the thumbnail card now reports the value instead of sending it.
- Fixed a negative `AmbientLight` colour or intensity whitening the image (the tone mapper turns negative radiance white): like the typed lights, an ambient value the renderer cannot use now keeps the last usable one.
- Fixed a scene camera saved with a value the renderer cannot use (a zero near plane, a non-positive radial transition length) failing the load of the game and of the Scene Designer's runtime view: the load now does what a later frame does, keeping the default projection and naming the member in `LevelRuntime.InvalidCameraProperty` until the value is fixed.
- Incremental builds no longer rerun the shader compiler (about 2.5 s per shader-consuming project) on every build after the compiler itself was rebuilt: it leaves an identical artifact untouched, so the build now marks the artifact current after compiling.
- Fixed a fresh checkout failing the VSIX tests (and every stage that runs them), `ecs.performance` and the hermetic clean build: the tools the build runs (shader compiler, scene schema writer, Feature Runner, Preview Host, VSIX bridges) and the ECS benchmark are now restored before they are built, the build runs them from its own outputs so `--artifacts-path` works, and the clean build passes its isolated package folder to the restores nested in the build and keeps its artifact root short enough for the VSIX packaging under MAX_PATH. Before, the clean build silently used the working tree's normal `bin` executables and VSIX.
- Fixed a fresh checkout failing to build the Feature Runner (and so CI's first step): its post-build VSIX compatibility check required Experimental evidence files that live under the untracked `.artifacts` root. Like freshness, the files are now required only by release validation (`--require-passing-evidence`).
- Fixed automation runs (`CGE_AUTOMATION_FRAMES`) depending on how fast the adapter presents: each automation frame now advances exactly the fixed-tick cap (8 ticks) through `EngineHost.FrameTime`, so a scripted run reproduces frame for frame on WARP and on a GPU. The ThirdPerson verification previously failed on a GPU, where the character was still in the air when the run ended.
- Radial depth keeps early depth rejection at every distance: each object's conservative raster depth now touches the encoded depth at the object's own view depth instead of one frame-wide 8 m tangent, so 24 overlapping layers at 100–1020 m take 0.12 ms instead of 1.74 ms on an RTX 4060 Ti. The Stage shader ABI is now `stage-v10`: `ObjectCB` ends with `RadialRasterDepth` and `FrameCB` no longer has `RadialRasterViewProjection`, so a custom Stage graph copied from an earlier one must be re-copied.
- Fixed radial depth losing precision on GPUs: the shader's `log2` is a hardware approximation, which put microscopic surfaces' depth percents off and reordered surfaces 5 cm apart at 20 km on an RTX 4060 Ti (WARP was exact). `log2(1 + x)` is now a float-only series, the same on the CPU; the depth is within 4 ulps of a double oracle in the middle of the view on both adapters.
- The editor's isolated preview (the Scene view of an unbuilt game and the Asset Preview) draws perspective views with radial depth from the editor's own matrix, and camera thumbnails follow their scene camera's depth mapping; orthographic views stay standard. The preview host protocol is now version 8 (`RenderPreviewCamera.DepthMapping`, `RadialTransitionMeters`); `RenderServer.SetViewProjection` takes `RadialViewParameters` for a radial matrix view.
- Radial depth is now the default of the scene `Camera` component: scenes without a `DepthMapping` member (including the ThirdPerson template and existing projects) render radial; write `"DepthMapping": "Standard"` for the hyperbolic depth. In radial mode the editor's runtime view clips with the nearer near and the farther far of the editor camera and the scene camera, so zooming out no longer cuts at the scene camera's far plane.
- Radial depth is now the default of the render camera factories (`Camera.CreateDefault`, `CreateFirstPerson`, `CreateBoundsFit`), so the viewer, the test host and direct `StageRenderer`/`RenderServer` users render with it; set `DepthMapping = RenderDepthMapping.Standard` for the hyperbolic depth (ADR-0076 addendum).
- Fixed edits of the scene `Camera` component not reaching a running view: the exposure, depth mapping and transition length (and, in the game, the field of view and clip range) are now read every frame, so a Scene Designer value edit or a game's own change shows on the next frame. An unusable value keeps the last usable projection and is named in `LevelRuntime.InvalidCameraProperty`.
- Fixed the world-space grid and the simplified height fog following the camera in the game and the editor's runtime view: the runtime renders camera-relative, and both now add the camera's world position back (the grid through an exact Q64.64 remainder per grid material). New `RenderServer.SetWorldGridAnchor` and `SetRenderOriginAltitude` (M0099 Phase 0, ADR-0075 addendum).
